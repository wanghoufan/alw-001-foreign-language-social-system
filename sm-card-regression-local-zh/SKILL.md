# 卡片回归（派生文件与真源一致性）

## 触发场景

- 更新任何 **Skill 卡片**（`SKILL.md`、登记档案、明细表、索引）之后。
- 更新任何 **活资料库**（技能地图、登记表、台账、清单、看板）之后。
- 出现「改了源但页面/清单没变」「两份卡片对不上」「计数对不上」「版本号/更新时间不一致」时。

> 用户 2026-11-05 明确：**不设口播触发词**。接手开发的大模型在遇到上述场景时必须主动调用本 skill，不依赖用户念口令。

## 这个 skill 解决什么

卡片体系通常有「真源 + 派生」两层：`SKILL.md`/源数据是真源，地图、登记表、台账、索引、页面展示是派生。改真源后忘记同步派生，或只改派生没回写真源，就会出现「看着改了、实际没变」和「两份数据对不上」。本 skill 把「改完必须回归核对」固定成一步，并给出统一回执。

## 适用 / 不适用

适用：

- Skill 新增、改名、改版本、改触发词、改描述后；
- 技能地图、中央登记表、明细表、项目台账、自动化登记表更新后；
- 活资料库（卡片库、清单、看板）增删改后；
- 发布或交接前的最终核对。

不适用：

- 只读查询、不产生任何写入；
- 纯代码改动且没有派生数据（走常规测试即可）；
- 用户明确说「只改一处、不用核对」——仍需在回复里说明跳过原因。

## 强制前置（机制二）

本 skill 是「机制二」：并入「卡片/活资料库更新」流程，作为**写入完成后的强制前置检查**。未跑本检查或缺少回执，不得报告「完成」。

## 执行流程

1. **列真源与派生**
   - 真源：`SKILL.md`、源数据 JSON/Markdown、主记录文件。
   - 派生：技能地图、`SKILL-REGISTRY.md`、`SKILL-REGISTRY-DETAIL.md`、项目台账、索引、页面展示、缓存副本。
   - 在回复里先列出「真源 → 派生」的对应关系，不能凭印象。
2. **逐对比对**
   - 名称：目录名、frontmatter `name`、登记名称三者一致。
   - 版本：真源 `version` 与登记表版本一致。
   - 更新时间：登记表日期不早于真源最后修改时间。
   - 内容：解决问题/触发词/描述与真源一致，无旧文案残留。
   - 计数：清单条数、分类计数、台账行数与真源数量一致。
   - 引用：派生里引用的路径/命令在真源中存在。
3. **差异处理**
   - 派生落后 → 修派生（不改真源）。
   - 真源写错 → 先改真源，再重新回归派生。
   - 两边都有 → 以真源为准，改完重跑一遍，直到无差异。
4. **产出证据**
   - 对文件类派生：`diff` 或逐字段比对输出（可截关键行）。
   - 对计数类：给出「真源 N / 派生 N」。
   - 对页面类：给出页面实际显示值或截图路径。
   - 证据落盘位置由项目约定；没有约定时写入 `docs/qa/<单元>/card-regression-YYYYMMDD.md`。
5. **输出回执**（见下节）。回执缺失或写「大概一致」不算完成。

## 强制回执（完成门槛）

收尾必须原样包含下面这段，任一字段缺失都不算完成：

```text
【卡片回归回执】
真源：<路径列表>
派生：<路径列表>
名称/版本/时间：一致 / 不一致（列出）
计数：真源 N / 派生 N
diff：一致 / 不一致（列出差异与处理）
结论：PASS / FAIL
```

## 验收标准

- 「真源 → 派生」对应关系已列出，不能只写「已同步」。
- 每个派生都有可复现的比对方式（diff 命令、比对字段或截图路径）。
- 不一致项已修复并重跑，或明确记录为「待确认」及原因。
- 回执五个字段齐全。
- 没有把「文件存在」当成「内容一致」。

## 常见坑

- **只比文件名不比内容**：改名了但内容还是旧版本，文件名一致不代表同步。
- **只改真源不改派生**：技能地图/登记表仍指向旧版本，用户看到的是旧卡片。
- **只改派生不改真源**：下次从真源重建会把改动覆盖回去（本轮 V1.6 双编辑入口就是同类问题）。
- **计数取缓存**：清单一侧来自缓存或旧快照，导致「计数一致」是假一致。
- **版本号改了但更新时间没改**，或反过来。
- **多份派生只同步一份**：地图、登记表、明细表、台账往往有 3–4 份，必须逐个核对。

## 红线

- 只读核对为主；修改派生前先确认派生来源，不得改用户其他项目文件。
- 不改真源来「凑一致」，除非确认真源本身错误。
- 不 commit、不 push、不部署；需要提交时由用户明确指令。
- 不把「已核对」写成「已修复」，两件事分开说。
- 不打印密钥、Token 或真实隐私数据。
