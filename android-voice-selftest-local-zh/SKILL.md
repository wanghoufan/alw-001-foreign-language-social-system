# 安卓语音链路自测（外放 / mock / 真人分层）

## 触发词

- 无固定口令，按场景自动命中〔用户〕

场景命中（任一）：需要在无人说话时验证实时 ASR、字幕、中文→英文、英文→中文、朗读；出现「外放自测」「手机没拾音」「识别成乱码」「注入 mock」；准备把一次语音相关验收报 PASS。

## 为什么要有本 Skill

语音类验收有三层，混写会直接造成假通过：

| 层 | 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 链路 | Mac `say` 外放 + 手机收音 | ASR 接入、页面渲染、翻译请求与回填 | 真人语音质量、真实环境噪声 |
| UI/接口 | 页面注入 `mock` 事件 | 气泡按钮、请求参数、回填与去重 | ASR 是否真的工作 |
| 真人 | 本人对着手机说 | 唯一可写语音 PASS 的层 | — |

## 执行步骤（强制前置）

1. **先判是否需要本流程**：本轮验收是否包含语音/字幕/翻译。不需要则跳过，并在报告写明「本轮无语音项」。
2. **判定层**：有真人在场 → 走真人层；没有 → 先试外放层；外放连续两轮无 `interim` → 允许降到 mock 层，但结论只能写 UI/接口。
3. **音源检查**（外放层）：
   - 确认 Mac 默认输出不是蓝牙耳机：`system_profiler SPAudioDataType` 查 `Default Output Device`；
   - 记录原音量（`osascript -e 'get volume settings'`），临时调到 90–100；
   - 中文用 `say -v Flo`（或 Eddy），英文用 `say -v Samantha`，语速 110–170，句子之间留 2–4 秒静默让 ASR 出 final；
   - 收尾必须恢复原音量。
4. **收音检查**：手机 App 前台、录音状态 `recording`；用 CDP 读 `#asrInterim`。连续说了两句仍无任何 interim，判「未拾音」，先排查（距离、音量、输入路由、USB 音频设备），**不得直接判产品缺陷**。
5. **断言**（按被测功能取用）：
   - 中文 final → 气泡按钮必须是「译英」；点击后 `/api/ai/draft-en` 返回 200，英文回填同一气泡；无空白 `.v152zh`；同 id 不重复请求。
   - 英文 final → 按钮是「翻译」；点击后出中文。
   - 暂停 → 外放期间 0 新字幕、无 interim；继续 → 新字幕接在同一轮。
6. **收尾**：`SocialMateAndroid.stopRecording()`；确认前台服务计数为 0；恢复音量；移除自己建的 `adb forward`；不卸载、不改系统设置。

## 强制回执（收尾必须原样输出，缺任一项不算完成）

```text
【语音自测回执】
音源：Mac 外放 / 注入 mock / 真人
收音：已拾音 / 未拾音（原因）
分层结论：链路 / UI 接口 / 真人
证据：<截图或 JSON/日志路径>
结论：PASS / PARTIAL / NOT_RUN
```

判定口径：

- **真人层**才可在「结论」写 PASS 并用于「语音功能通过」。
- **外放层**通过写「链路 PASS」，同时注明识别文本可能失真。
- **mock 层**只能写「UI/接口 PASS」，必须标注 mock。
- 未拾音、未执行、结果读不出 → `NOT_RUN` 或 `PARTIAL`，不得写 PASS。

## 红线

- 不得把外放或 mock 的通过写成真人语音验收。
- 未拾音时先排查音源与输入路由，不得写成产品缺陷。
- 注入 mock 事件必须留下注入记录（事件体、时间、mock=true）。
- 临时改动的音量、分辨率、forward 必须复原；不卸载应用、不改系统设置。
- 不打印密钥、令牌或语音原文到公开日志。
