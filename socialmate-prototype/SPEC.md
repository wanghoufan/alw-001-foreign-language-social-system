# ALW-001 SocialMate · SPEC — 产品架构 / 页面设计 / 数据交互 / 正式实现

版本 1.0｜2026-10-31｜本文件随 socialmate-prototype/index.html 一同交付；以正式产品资料为准。

## 0. 本次设计目标与现状事实

目标是在海口或其他场合与外国朋友交流时，只靠一部安卓手机：
- 平时准备：用中英双语熟悉自己的软件、海南地点和自己的人生故事；
- 现场：快速查到相关资料，简短复制/展示/转发；英语 ASR 实时转写，在说话间提示自然追问、分享和相关知识；
- 会后：保留原始英文及时间戳，核对谁说了什么，将**确实确认的对方信息**并入其人物档案，下次见面能继续话题。

已存在的正式资料：
1. 软件作品集 `docs/成果整理/2026-10-31 - Mac Mini - ChatGPT - Bilingual Software Portfolio-Demo Guide - V1.4.md`，51 产品条目，204 条原编号演示步骤；不使用 temp/intros-A~I 替代。
2. 海南地点 `docs/成果整理/Hainan-Travel-Guide/baseline/places.json`，115 中英地点、分类、导航及图片来源标记；不修改原始文案。
3. SocialMate-Data 的英文句型、聊天话题模板、私人 Markdown 人物档案（含虚构 Test-Anna）、已有 `/api/preview` 和 `/api/apply` 人工确认写入。
4. BOYA mini + 红米已录到 48k 双声道，但两轨同源，为当前 `MONO_MIX`；Android APK 0.2.2 已构建并运行，ASR bridge 已做 MOCK 联调；**真实腾讯云识别尚无验收**。

## 1. 最终信息架构（手机底部五主 Tab）

| Tab | 核心目的 | 首屏布局 | 进入详情 | 现场操作 | 是否公开 |
| --- | --- | --- | --- | --- | --- |
| 软件 | 介绍自己开发的软件 | 一句话引导；即时搜索；APP/PWA优先筛选；两列桌面/一列手机卡片 | 右侧/底部抽屉：中英简介+P 编号+1/2/3/4 演示 | 复制英语、加入聊天参考 | 仅通过公开内容筛选后 |
| 海南 | 推荐当地去处 | 中英搜索；城市/分类筛选；双语地点卡 | 双语详细介绍、地图链接、已有授权图片（若有） | 分享给朋友、复制、加入聊天 | 可以做只读公开版本 |
| 聊天 | 辅助现场交流 | 对话原文主区域；即时资料参考；英文追问/分享短卡 | 原文详情、对应知识来源 | 启停、查资料、点卡片、确认归档 | 永不公开 |
| 关于我 | 方便表达个人经历 | 生活/兴趣/经历标签、中文事实与自然英语 | 单张卡片修改、确认状态 | 复制、固定引用 | 私人；每张允许单独授权公开 |

手机导航位于底部并考虑安全区；横屏/桌面使用左侧主导航。五个 Tab 是全局路由，不在页面塞重复的跳转卡片。原有「练口语」「AI 整理」移至各自场景内的次级操作，不再占用额外底部 Tab。

## 2. 关键页面布局与交互

### 2.1 软件：已整理的作品集不再重写

- 优先 A 类手机 APP/PWA，再 B 类特殊场景可访问产品，C 类桌面/后台。
- 关键词可搜 P 编号、作品中英文名、CN/EN 简介。列表第一屏显示分类和可演示性，避免展示“已发布”假象。
- 点击卡片时弹出层级详情，不丢列表筛选状态。详情从上至下：名称/P ID → 中文总介绍 → 自然英语 → 复制/加参考 → 1-4 编号步骤 → 未核实操作说明。
- 对外分享只使用确定公开的演示链接；私有仓库不能当成朋友可打开的网址。
- 源数据从 V1.4 完整导入，不重新发明步骤；源主稿更新时必须全量重新生成、审核条目数/编号/步骤。

### 2.2 海南：以介绍/地图/分享为主，不做景点信息站

- 上方全文搜索，中间城市下拉与分类横向标签，下方地点卡片。手机单列，词短、图轻、英文易读。
- 详情保留原中英简介、分类、城市、地图查询链接，提供系统分享 API 和复制回退。
- 现场聊天示例：朋友说 “I love the outdoors.” → 内容检索“nature/outdoors/park” → 首选适当的万绿园等场所，按真实资料推荐英文表达。
- 115 地点的图片有下载/授权不全问题。原型可在本机使用存在的文件，发布公开分享页之前必须逐张核版权与来源；缺图使用文字卡，不编造景点照片。

### 2.3 聊天：实用优先，别把对话搞成 AI 论文

实时使用时优先看到：**当前说话文字、谁说的（可未知）、一条自然追问、一条可分享的话、可检索参考来源**。
- 说话人位置可为我 / 对方 / 未确定，不能把 spk_0 当真实姓名。
- 实时英文转写的最终句不可由模型改写；interim 可以覆盖，final 必须以稳定 ID 追加或正确替换同一句，避免重复。
- 推荐理由与文档来源要可追溯（P 编号、Hainan id、Story id）。
- 建议结构三层：① 一句追问 ② 一句可用的个人分享 ③ 一个相关资料卡。最多常显 2–3 项，避免喧宾夺主。
- 用户主动选人物；后续产品可建立会话快照、逐人关联、收藏话题、语音质量和网络状态。
- **本原型没有开麦或发网络请求**，采用手动输入模拟 ASR，保证可在家独立演示页面交互。

### 2.3.1 聊天区自动建议契约（2026-10-31 用户纠正，必须遵守）

**用户明确要求：语料区不是搜索栏，而是 AI 根据双方实时对话自动弹出的上下文建议。搜索只是备用工具，默认折叠。**

完整的正式用户路径：
1. 原生 AudioRecord 采集博雅混音，送入腾讯云 ASR；只使用被确认的 final 字幕触发稳定推荐（必要时对 interim 做低频、可替换预览）。
2. 服务端以最近 3–5 轮对话、当前话题及本人已经确认的资料为上下文，判断“对方在说什么、我能如何自然接、下一步如何追问”。每次话题切换或对话内容推进时自动刷新推荐，不要求用户再点击搜索。
3. 首先显示 **① 自然接话（1句）② 连续追问（按顺序推荐2–3句）③ 我能分享的事实或建议（1句）**，不要让 AI 一次输出十几段大作文；不要编造用户经历或朋友事实。
4. 同步从正式 **海南115地点、软件V1.4的51条目/204步、关于我已确认话题** 做带来源 ID 的多路检索。优先关联与当前对话实质相关的地点/作品，不为凑数硬推；没有可信命中宁可显示“本轮暂无相关资料”。
5. 资料卡自动呈现**来源类别、名称、英语简述**。**整张卡可点**，点击后导航到“海南/软件/关于我”的正式详情，含中英原文、地图/复制/分享；显式“返回聊天”，保持会话不丢失。卡片不只是复制英文。
6. 可以在备用的折叠入口手动查，但不得要求用户先输入关键词或点击“查资料”才能得到内容。
7. 应区分 UI 更新与真实云能力：当前 HTML 的“自动话题”基于预设规则做交互模拟，**没有接腾讯云 ASR 或大语言模型，不能宣称 AI 实际自动推送已上线**；正式集成要实现服务端实时触发及真实语料的证据追踪。

示例验收：
- 输入或识别 “I like running outdoors near the sea.” / “户外跑步” → 自动产生跑步场景接话 + 多轮英文追问，并关联 **万绿园 (NO.39)、海口湾滨海步道 (NO.41)、白沙门公园 (NO.45)**，来源均为正式海南地点库。
- 点 NO.39 → 海南详情完整原文/地图/分享 → 返回聊天仍能看到刚才的对话；无需手动搜索。
- 说话人不确定不冒充某人的个人偏好；新话题出现后推荐更新；一句“嗯”“yes”不应把当前话题全删。
- 若 ASR 断线/数据未加载 → 保持已有最后可信推荐并标注过期、提供恢复路径，不把之前的卡片冒充即时 AI 输出。

**UI 顺序：对话原文 → 自动接话/追问 → 自动相关资料卡 → 折叠备用搜索。** 手机时这些内容逐段显示，桌面时分栏。用户当前在家不能真人录音，先用模拟字幕做功能闭环，真机 ASR 是最终验收。

### 2.4 关于我：事实优先、自然英语次之

- 中文事实 / 一到两句自然英文 / 标签 / 已确认状态。
- 个人信息必须来自用户确认或其提供的文档。不可生成“自己去过某地”“对方喜欢某运动”之类无证据句子。
- 可搜索、临时收藏到聊天参考、复制发送。新增编辑只落浏览器本机原型，不自动更新服务端。
- 正式产品应由用户在手机上编辑并同步到私有 Markdown 资料库，提供同步失败回退/本地草稿。

### 2.5 人物与会后：只存已确认事实

- 每次会话记录分离为 `raw_transcript` (不可改原声文本)、`reviewed_note` (人工可编辑)、`person_facts_pending` (未确认候选)、`person_facts_confirmed` (已确认)。
- 人物主档和新互动的写入必须经过 preview→apply。乐观锁与冲突回滚沿用已有服务。
- 没有名字或说话人不确定时归到“未关联会话”，不擅自强行关联。
- 已确认信息写入人物 notes，记录来源会话和日期，不能越界读取对方隐私。
- 真实用户数据和虚构示例显式分离。

## 3. 数据源与字段契约

本原型 `data.js` 是**构建产物**，不是可编辑源。由 `build-data.cjs` 读取正式文档生成：

```text
SoftwareCard:
  id: "P005"                      // 固定 P 编号，永不重排
  name, category:"A|B|C", group
  cn, en                        // V1.4 原文，不 AI 重写
  mode, needVerify              // 证据强度提示
  steps:[{no,cn,note,en}]        // 保留原编号及语义

HainanCard:
  id:3, name:"骑楼老街", enName:"Qilou Old Street"
  city, category, cn, en, location
  mapAmap, mapGoogle            // 原有地图导航
  img, photoStatus, warning     // 未经授权不要对外分发

StoryCard:
  id, title, topic, cn, en
  status:"confirmed|review"
  keywords                     // 简单别名索引

Person:
  id, name, about, interests, notes:[{date,text,sessionId,confirmed}]
Session:
  id, date, source:"manual-demo|tencent-asr", personId
  messages:[{speaker,text,time,demo}], reviewed_note, confirmed
```

检索实现阶段：
- 原型：本地字符串匹配 + 英文常见词过滤和少量语义关键词映射、双语全文搜索，**不是 AI 语义检索**；200 条左右无需复杂数据库。
- 正式 APP/服务：建立规范化索引，英文分词/词形化 + 中文分词和同义词表，保留 `source_id`、`last_verified`、`visibility`。只有语料库规模和错误率证明必要时才引入向量检索。
- 可视化引用卡必须能打开对应正式原文与编号；不能由大模型凭空生成地点坐标或软件按钮。

## 4. 正式技术方案与现有工程集成

### 4.1 客户端：Android 原生录音，HTML 与数据共用

- 继续用已构建的 `android-poc` 作为原生音频验证基础。正式实时采集使用 `AudioRecord`，单手机 USB-C BOYA mini，默认 **mix**。如以后分轨成功再开放高级 A/B。
- 录音业务逻辑由 Android 原生层掌握；UI 可以选择 Jetpack Compose 原生化，或使用 WebView 承载经过审核的静态 HTML 内容页。不依赖手机厂商内置浏览器支持 getUserMedia。
- 本原型 `socialmate-prototype` 与现有 `android-poc` **目前不合并**，避免开发者并行写冲突。集成时先同一个任务窗口领取目录所有权，再决定技术路线。
- 当前已实现 `public-share.html` + `public-places.js` 公开只读 HTML 原型，只含 115 海南地点，支持按 `?place=id` 浏览、英文/中文、搜索、地图和分享；尚未部署为真正 PWA。公开 PWA 不承载常驻麦克风；在用户的小米/红米/OPPO 自带浏览器上优先 QA，不把 Chrome 通过视为全机型通过。
- 浅色是默认，深色可切换；手机安全区、单手可达、字号、低电量和离线可浏览是基本要求。

### 4.2 音频、ASR、建议

```text
2 × BOYA 发射器
       ↓ (当前为 dual-mono 混音)
BOYA USB-C 接收器 → Android AudioRecord 48k PCM
       ↓ (前台采集 + 用户明确开始/停止)
Mac mini 私有 ASR bridge → mono / 16kHz / PCM16
       ↓
腾讯云实时 WS（16k_zh_en_speaker_2.0）
       ↓ (原文+时间+speaker_id+终稿标志)
逐句话题识别器 → 51 软件 + 115 海南 + 已确认私有话题
       ↓
轻量建议服务（有/无模型都能回退）→ Android APP 实时提示
       ↓
会话结束 → 私有会话原文、审核候选 → 用户确认 → People 主档
```

安全要求：密钥仅在 Mac mini 服务端；手机不得硬编码 SecretId/SecretKey；公网传输须 TLS/wss、鉴权及请求频率控制，服务默认私有；严禁把原始录音和私人资料发到公开 PWA。被录音者应知情同意，具有清晰的正在录音显示、停止与删除入口。

断网：会话状态可恢复、音频帧有序号/确认边界、不会重复归档同一句；不应暗示离线仍可进行云 ASR；本地资料和已有文稿仍应可查阅。锁屏/后台仅在 Android 端具备符合平台要求的前台服务和合法权限后才能启用。

### 4.3 服务端接口建议（新增，不污染旧接口）

- `GET /api/library/search?q=&scope=software,hainan,self` 返回已授权过滤的参考资料（私有查询需认证）。
- `GET /api/library/:kind/:id` 返回准确版本、原文、中英及来源。
- `POST /api/sessions` 创建带幂等键的会话，指定人物/知情同意状态。
- `POST /api/sessions/:id/events` 追加**原始稳定句**、时间戳、说话人、云端状态与来源；只追加不覆盖。
- `POST /api/sessions/:id/review` 存用户确认的整理内容，检查源会话版本。
- `POST /api/people/:id/facts/preview` → `apply` 沿用现有双阶段确认机制，禁止未经确认直接写真实主档。
- `GET /api/public/places/:id` 与分享页只返回发布白名单中的资料，图片必须有许可字段。

无权或无密钥时，前后端应回退到静态资料检索/手动会话，而不是报“全部功能不可用”。

## 5. 性能、浏览器和可访问性标准

- 51+115 数据包离线可用，首屏应流畅，搜索打字不应丢焦点。数据加载失败应给出错误提示，不能白屏。
- 最小可触控控件 40–44px，底部导航安全区适配；五主 Tab 固定，页面详情使用抽屉/返回，不能出现嵌套多层弹窗。
- 支持 Android 360/393/412/430px、横屏和 768px / 1024px / 桌面宽度；手机浏览器优先 Xiaomi Browser、Redmi/Mi Browser、OPPO Browser，Chrome 仅补充。
- 状态明确区分：模拟文本、ASR 中间稿、ASR 最终稿、身份未知、确认归档；不能把 mock 当真实结果。
- 无网络时页面能打开静态资料；地图/真实 ASR 可显示需要网络。复制应有反馈；Web Share 不支持时回退复制。
- 内容中英可选中、可放大；兼容操作系统深色但首次打开**默认浅色**；不会强制禁用系统字体缩放。

## 6. 技术 QA 与产品验收

原型技术测试：脚本语法、51/204/115 数据断言、五 Tab、软件功能详情、海南卡片与地图、固定参考、全库检索、浅/深色、演示会话知情说明、建议命中、审核归档和人物 notes。配套 `test-prototype.cjs`。

真实环境最终 QA：红米真机、BOYA mini、腾讯云实际转写、speaker_id / 断线恢复、性能和授权；安卓与 PWA 各自测试。不得在没有实机、真实账号和真实人工验收时标记已通过。

## 8. 交付标准与工作区并行治理

本轮 HTML 原型应以 `socialmate-prototype/` 为完整独立交付单元；其他开发者可以继续 `android-poc/` 和 `asr-bridge/`，但当前不修改本目录，避免互相覆盖。不可 `git reset --hard` / `git clean` 清掉别人的未提交数据。

## 新增：正式 AI API 选型与调用契约（2026-10-31）

### 已确认 API（用户指定）

- **默认 DeepSeek 官方通用接口** `https://api.deepseek.com/chat/completions`；默认模型 `deepseek-flash`（官方当前映射 V4.1 Flash），可选 `deepseek-v4-pro`。官方 Flash 以 `thinking: {type:"disabled"}` 为日常聊天关闭长思考。配置键：`DEEPSEEK_API_KEY`。
- **备选 OpenCode Go** 官方最新兼容端点 `https://opencode.ai/inference/go/openai/v1/chat/completions`；模型 `deepseek-v4.1-flash`；独立 `OPENCODE_GO_API_KEY`，不同于 DeepSeek 官方 Key。若官方路由有变更仅允许通过 `OPENCODE_GO_API_URL` 在白名单官方地址中切换。
- 已真实编码的隔离模块 `socialmate-prototype/ai-gateway/core.mjs`、`server.mjs`，用户通过 HTML 选择模型、勾选发送对话内容的独立同意后，调用 `POST /api/ai/analyze`；成功返回 `mode:real-ai`、模型名、回复、2–3 个自然追问和真实资料 ID。无 Key/无权限/超时时明确说明并显示「规则回退」，**不把 fallback 冒充真模型**。
- 从对话中选择最多 12 个候选；模型只可引用已有 115 海南地点、51 软件和（额外授权时）已确认的个人话题 ID；服务端独立校验 LLM 输出引用，杜绝凭空创造地点卡。
- 为避免频繁付费，服务端同一时间仅允许一个模型请求，两个请求至少间隔 1.2 秒。ASR 正式接入仍必须在最终句 (final) 后去重/节流，不能对每个 interim 都计费。
- 本机服务只绑定 127.0.0.1:8791；正式跨设备访问前必需 TLS、鉴权和已同意的会话传输规则，严禁公开含私人资料的工作台。
- 该 API 模块目前处于**源代码与离线模拟调用通过阶段**，未取得用户 Key 的真实提供商连通、真实费用和建议准确率；必须单独验收。

### 开工硬依赖及可先推进部分

真实 AI 验收需要用户确认 DeepSeek 官方 API Key 与额度（默认硬依赖）；OpenCode Go 可选线路需要 Go API Key、可用套餐余额及必要的 Global 地域许可。两者不是同一套额度，不能默认为用户在 OpenCode 客户端登录就意味着可通过本服务调用。开发者应先自检现有合法授权的本地配置（不得打印 Key），未具备才集中向用户提出必要设置。

**过去遗漏该 API 预检是不合格的开发入口，之后所有 LLM 相关功能均应在开工时预检 Key/余额/正式响应。** 麦克风真人实测暂不阻塞模型文本链路与 UI。

## 用户自主显示偏好与内容优先布局 · UI V1.2（2026-10-31）

已按用户反馈实改 `index.html`、`app.js`、`styles.css`：

- **不出现每个一级 Tab 顶部的大块绿色介绍 Hero**。首屏直接是搜索、分类标签、软件/海南/个人资料卡或聊天原文；不应以产品宣传文字占用主要可视面积。
- 手机右上角新增独立**显示设置**按钮（不是新增第六个底部 Tab），提供：整体文字大小「标准/较大/大字/超大」、英文阅读字号「标准/加大/特大」、内容密度「紧凑/舒适/宽松」、浅色/深色主题。更改立即作用于五 Tab，保存至浏览器 localStorage，下次同浏览器恢复；具体数值不是不可调的用户硬限制。
- 默认正文约 **16 CSS px**（1rem）、次要标签约 **14 CSS px**（.875rem）、英文正文约 **18 CSS px**（1.125rem）、行高约 1.65–1.7。大字档整体正文约 18/20/22px，英文可以单独再放大；用户浏览器或系统缩放不能被禁止。不要将简短说明压回 10–13px。
- 紧凑/舒适/宽松只影响卡片内边距、列表间距和区块留白，**不允许用缩小文字来增加单屏密度**。字体变大时正文自动换行，卡片高度自然增加；英文卡片不以固定 2 行裁切，详情文字不得因固定高度被遮挡。
- 「关于我」在搜索下方显示动态标签（来源为个人话题的分类及自定义多标签），支持编辑时输入多个标签并点击快速筛选；未来内容规模增加无需改页面代码。正式个人主档仍应使用系统人工确认和单一数据源，不自动改写原始 Markdown。
- Android 原生版本用 `sp` 支持系统字体缩放；Web/PWA 用相对单位、允许浏览器 200% 放大、响应式换行并检查 320 CSS px reflow。上述仅是 QA 目标，不冒称已经达到 WCAG 2.2 AA 完整合规。
- 真实验收：320/360/390/430/768/1024/1440px，标准与超大、紧凑与宽松、两主题、弹窗、横屏、滚动、记忆及英文完整性；红米/小米/OPPO 自带浏览器须单独验收。独立便携 HTML 目前只含 23 个海南预览样本，正式项目的 `data.js` 仍保留 115 个。

参考：W3C WCAG 2.2 SC 1.4.4 Resize Text 和 SC 1.4.10 Reflow；Android Developers 的 Material 3 Typography 与 Text Scaling 文档。**不是把 Material 的 12px 次级字号作为本产品推荐字号**，本产品优先满足用户实际阅读舒适度。
