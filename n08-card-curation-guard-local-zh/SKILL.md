# N08 复习卡内容门禁（ALW-001）

本项目的复习卡由「课程索引 → 大模型策展 → 质检 → 入库」四步生成。2026-11-16 一天内因为跳过其中任一步返工六次，出报告前逐条过。

## 触发场景

- 改 `scripts/n08-course-index.mjs`（抽取规则/兜底）或重生成 `socialmate-v1.2/source/n08-course-index.json`；
- 跑 `scripts/n08-curate-cards.mjs`（大模型策展）；
- 往 App 预置课程卡（`source=course` 的条目）；
- 用户说「转复习卡没反应 / 泛化太浅 / 卡片重复」。

## 七项检查

| # | 检查 | 判据 | 本项目踩过的坑 |
|---|---|---|---|
| 1 | 字段按真实 JSON 读 | 先 `python3 -c` 打印一条记录的键名，再写解析 | 实际是 `items[{text,zhHint,keywords}]`，却按 `c.zhHints[i]` 取 → 转卡永远 0 条 |
| 2 | 原句逐字 | 只允许补句末标点、首字母大写；其余一字不改 | 模型「顺手改写」会把课本句改掉，复习就失去参照 |
| 3 | 泛化是句式变式 | 覆盖 ≥2 类：`person` 换人称（含三单）/ `form` 陈述↔疑问、肯定↔否定 / `object` 换对象 / `tense` 换时态；每条只改一处，≤10 词 | 只写「换一个词」→ 模型拿同义词交差（chilly→cold、may I 冒充句式） |
| 4 | 生成后必过质检 | 第二遍调用逐条判「骨架一致 / 语义通 / 标签对 / 长度」，不合格删或改写，记录前后条数 | 未质检时出现「他真的很冷 → he is really chilly」这种把天气句套到人身上 |
| 5 | 条数按内容量 | 上限只防刷屏（本项目 12）；按本课总结取舍，不硬凑不硬砍 | 早期写死每课 3 条，长课 20 多句只出 3 条 |
| 6 | 入库去重 | 按规范化英文去重，重复只累加 `count`，不新建卡 | 同句在「原句/变式」里出现两次会建两张卡 |
| 7 | 真机验证 | 点「转复习卡」后条数变化、组包后 `packId + 题数 + 模式分布` 有具体数字 | 只跑脚本不看设备，字段错也「通过」 |

## 强制回执（缺项不得报完成）

```text
【复习卡门禁回执】
字段核对：<索引真实键名>（已打印 1 条）
原句来源：逐字取自 <courseId 列表>，补标点 <n> 处
变式类型：person <n> / form <n> / object <n> / tense <n>，覆盖 <n> 类
质检：生成 <a> 张 → 留 <b> 张，删除/改写 <c> 张（原因：…）
条数：每课 <min>–<max>（上限 <上限值>，未硬砍）
去重：新增 <n> 条，重复跳过 <m> 条
真机：转卡后条目 <x>→<y>；组包 <packId>，题数 <q>，模式分布 <m1/m2/m3>
结论：可入库 / 存在阻断项（列明）
```

## 边界

- 只做判定与取证，不改业务代码；发现不合格卡回到 `scripts/n08-curate-cards.mjs` 调提示词重跑。
- 质检结论必须写清「删了什么、为什么」，不接受「优化了一下」。
- 设备侧操作仍走 `android-true-device-qa-orchestrator-local-zh` 的覆盖安装与清场流程。
