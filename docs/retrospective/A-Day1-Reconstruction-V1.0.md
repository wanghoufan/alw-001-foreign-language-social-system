## §3 完整使用旅程（站在终点反推的真实用户路径）

### 3.1 首次运行（一次性）

1. 确认 Node 20+（README.md:24）。
2. `node scripts/initialize-data.mjs` → 在项目根内生成 `SocialMate-Data/`（25 个目录 + 12 个文件），含虚构演示人物 `Test-Anna` 与国庆话题包（README.md:27；`initialize-data.mjs:20-25`）。
3. `node server.mjs` → 终端打印 `SocialMate: http://127.0.0.1:4173 (data: ...)`（`server.mjs:118`）。
4. 浏览器打开 `http://127.0.0.1:4173`。
5. 若 4173 被 Docker 正式容器占用 → 改用 `PORT=4174 node server.mjs`（README.md:34；HANDOFF.md:41 明确「不得擅自停 Docker 容器」）。

### 3.2 日常四步主流程（首页即流程图）

首页 `Today` 直接把四步画成 01–04 卡片（`public/index.html:89`）：
- 01 准备聊天话题 → 跳 `Topics`
- 02 练习英语对话 → 跳 `Practice`
- 03 整理真实交流 → 跳 `Review`
- 04 查看人物资料 → 跳 `People`

### 3.3 分支 A：准备话题（Topics）

左侧话题列表（支持搜索框即时过滤，`index.html:93,137`）+ 右侧阅读区渲染 Markdown（`markdown()` 自实现，`index.html:45-64`，先 `stripFrontMatter`）。选中的话题写入 `sessionStorage['sm-topic']`，下次自动回到上次读到的话题（`index.html:131,138-139`）。

### 3.4 分支 B：练口语（Practice）

选场景（海口健身房/咖啡店/酒吧/第一次见面）+ 5 档难度（很友好→自由实战，`index.html:16,95`），点「生成提示词」→ 生成一段约 10 分钟、含固定文件名规范与固定 YAML 字段 Markdown 结构要求的提示词 → 点「复制提示词」→ 粘贴进 ChatGPT Live。练习结束后 Live 侧产出可下载 `.md`，用户**手工**放进 `SocialMate-Data/Practice/Sessions/`（`index.html:194`；README.md:65）。

**注意这个断点**：练习结果回到本地靠人手动搬运，且 Live 无法访问本机文件系统——提示词里专门写了「你无法直接访问我本机文件系统，不要声称已保存到该路径」（`index.html:194`）。这是 2026-10-06 才补上的认知（见 §4.3）。

### 3.5 分支 C：整理真实交流（Review）

页面只有一个按钮「复制完整整理提示词」。提示词内含：项目绝对路径、资料根目录绝对路径、7 条整理规则、以及一段待填的口述占位（`index.html:101-118`）。用户复制到「能访问本项目文件的 AI」，由 AI 写文件。**网页本身不调用任何 AI**（`index.html:97` 明写「这个网页不会替你调用 AI」）。

### 3.6 分支 D：人物档案（People）

表单建档（姓名必填/国家/城市/语言/兴趣，`index.html:91`；后端校验 `server.mjs:54`）→ 卡片网格 → 搜索框按姓名或路径过滤（`index.html:159-169`）→ 点「打开档案」就地展开渲染后的 Markdown（去 front matter，`index.html:150-151`）。

### 3.7 主题与导航

左侧边栏底部三段式主题切换：晨光 / 墨夜 / 松林，写 `localStorage['sm-theme']`，`<head>` 内联脚本防闪烁（`index.html:3-10,28-33`）。五个功能用 hash 路由直达与前进后退（`index.html:69-73`）。

## §6 V1 必须有 / 明确不做（反推结论）

### 6.1 V1 必须有（按「缺了就不成立」排序）

1. **Markdown 为唯一数据真源**，目录结构固定，模板可生成（`initialize-data.mjs:5-25`）。
2. **两个写保护**：主档改动必须预览→确认（含 baseHash 防陈旧）；互动记录只增不覆盖（`server.mjs:74-103`）。
3. **路径越界防护**：拒绝 `..`、绝对路径、反斜杠（`server.mjs:26-31`；测试断言 `test:82`）。
4. **只绑回环地址**，无账号、无云同步、无 AI API（`server.mjs:10`；README.md:5）。
5. **五个入口齐全**：Today / People / Topics / Practice / Review（`index.html:15`）。
6. **中文文件名与 UTF-8 全链路正确**：创建、读取、排序（`server.mjs:35` 用 `localeCompare('zh-CN')`；正则 `server.mjs:19` 用 `\p{L}\p{N}`）。
7. **AI 不内嵌**：以可复制提示词形式外挂（`index.html:97,101-124`）。

## §10 哪些改动仍属不可避免的真实迭代

## §13 终审素材包（A 路）

本项目的本质是一次「需求写得极好、外观与导航没写」的执行。原始方案文档（781 行，2026-10-04，现仅存于被 gitignore 的 `temp/`）在数据真源、隐私红线、目录结构、五个入口、Test A–G 验收、安全要求、禁止事项上都写得异常清楚——清楚到开发者几乎可以照着写，这也是 `151aa27`（2026-10-05）一次提交就交付了后端 + 前端 + 初始化 + 7 个验收用例（+1102 行）的直接原因。真正出问题的地方只有一块：外观与导航。原方案在 §10 写「不要过度设计 UI」、在 §18 写「在 Human Gate 前不追求视觉完整度」，这两句话被理解为「外观可以以后再说」，于是外观既没有被定义，也没有被排期。结果是在 2026-10-11 一天之内，连续四次提交处理同一件事：`b8b78df`（13:32）做完三主题与整体交互，`f2e4dbc`（13:35，3 分钟后）把切换器从下拉菜单改成顶栏分段控件，`00aec27`（14:22）删除「跟随系统」并把默认改为晨光，`262ac05`（14:30）把顶栏导航整体改成左侧边栏。四次改动里有三次是把已经做完的东西推倒重来，而这三次的答案——主题有几套、默认是哪套、切换控件长什么样、导航在左边还是在顶上——全都是用户在第一次开口时就能回答的问题。

第二个值得终审注意的结构性问题，是「真源不止一个」。用户手改的 `SocialMate-Data/00-README.md`（mtime 2026-10-05 11:11，含「## 口语练习学习材料」章节）与 `scripts/initialize-data.mjs:6` 生成的同名文件（不含该章节）已经分叉；一旦换机器重新初始化，数据规范就会少一章。同一类分叉还出现在部署侧：源码 HEAD 与部署副本逐字节一致（本次实测 diff 0 行，是好事），但容器挂载的数据目录 `~/DockerData/alw-001-foreign-language-social-system/` 的 mtime 停留在 2026-10-05 11:10~11:11，与项目内数据目录不构成可验证的同一份。再加上前端提示词里硬编码了 `/Users/zzymima0000/Developer/coding/1.Active/alw-001-外语社交系统`（`index.html:104-105`），这个项目目前「只在这台机器的这个路径下成立」。

第三个终审要点是证据链本身的损伤。`5698685`（2026-10-11 14:55）把 781 行原始方案文档从版本库删除，只在工作树的 `temp/` 留了一份被 gitignore 的副本；任何未来的 clone 者都看不到 Day1 需求原文，只能看到 README 与代码。同期还有 `bef53d0` 补英文 README 与 Docker 说明、`b956852`/`5698685` 两次清理，推断（无直接证据）是为公开或分享做准备。这个动作让「历史覆盖度」出现了硬缺口：本文件 §4 对原始需求的全部引用都依赖一份不在版本库里的文件。

第四，质量验证这一层是「后端很强、前端为零」。`test/acceptance.test.mjs` 的 7 个用例覆盖了建人物、加互动、沟通卡、话题包、练习提示词、重启持久化、预览—确认—拒绝陈旧—路径越界，本次实测 7/7 通过（Node v24.19.0）；但没有任何 UI 自动化测试，界面正确性只靠 HANDOFF.md:15 一句人工实测记录。同时 README.md:60 写的 `node --test` 在带上目录参数时会报 `MODULE_NOT_FOUND`，说明验收命令没有被固化到可复制粘贴的程度——而原方案 §13 恰恰把「测试闭环」写得很细，只是没有把它落到命令与 CI 上。

最后给终审一句话结论：这个项目最该被记住的经验不是「Local-first 怎么做」，而是「**外观与导航不是可以以后再说的细节，它们是 Day1 就要问完的一组是非题**」；以及「**凡是同一个规范同时存在于生成器和手改文件里，迟早会分叉**」。
