## 2. 分级结论

> P1 = 影响核心信任/引导必然失败的操作；P2 = 明确产品缺口或高频痛点；P3 = 打磨项；Future = 机会与方向，不建议现在动手。

### P1（2 项）

**R1-P1-01 桌面端「开始录音」按钮误导（无桥提示缺失）**
- 视角：普通用户 / 容错性 / 状态反馈
- 现象：桌面浏览器打开 8791/v12 聊天页，按钮文案为「开始录音」；点击后真实 ASR 会话无法由浏览器发起（原生桥函数不存在）。代码 `hasRecordingBridge()?t('chat.start'):t('chat.start')` 两分支同文案，说明"区分分支"从未实现，这与 HANDOFF T6③「桌面预览无桥提示未检出」互相印证。
- 影响：桌面预览者（包括接手的新开发者、被分享内网链接的人）被引导执行**必然失败**的操作；失败后的反馈也不足以解释"为什么录不了"。
- 建议：无桥时按钮改为「在手机 App 中录音」或置灰 + 一句说明（"录音由 Android App 提供，桌面仅预览字幕与建议"）。这是一处文案/状态分支的最小修复，不动音频层。

**R1-P1-02 公开 PWA：详情返回后列表滚动位置丢失**
- 视角：高频用户 / 操作效率
- 现象：实测滚动至列表 2500px 处 → 打开任一详情 → 「Browse all 115」返回 → 列表回到顶部（`scrollY=0`）。筛选与"想去"选择保留了，但滚动位置未恢复。Product Plan V1.2 工作流 A5 明确要求"修复移动端详情返回后列表滚动与筛选/选择不丢失"，本轮实测**滚动恢复仍未达成**。
- 影响：朋友翻到第 50+ 个地点再点进详情，回来要重新长距离滚动；这是浏览 115 条地点的高频路径。
- 建议：返回时恢复列表 `scrollY`（内存或 `history.scrollRestoration` 均可）；顺带验证浏览器返回手势路径与「Browse all 115」路径行为一致。

### P2（3 项）

**R1-P2-01 「关于我 / 人物」数据仅存浏览器 localStorage，同步闭环未打通**
- 视角：产品经理 / 功能完整性 / 容错性
- 现象：UI 已诚实标注「仅本机草稿 · 未同步 Mac」「点『同步到本机档案』并确认后才写入」，且同步需显式确认（符合红线）。但「同步到本机档案」之后的正式档案链（→ `SocialMate-Data/Profile/` → People Markdown）在 Web 端未闭环（README 与 HANDOFF 均承认）。
- 影响：高频用户积累的草稿、收藏、人物记忆随浏览器清理而丢失；换浏览器即"失忆"，与产品"本地知识库"定位存在张力。
- 建议：短期在设置页给「当前浏览器存储体量 + 导出 JSON 备份」入口；中期打通同步链并把"草稿未同步"状态提升为聊天页可见的轻提醒（而非只在关于我页内说明）。

**R1-P2-02 Android「无 USB 使用」核心目标未闭环（手机 Tailscale 未登录）**
- 视角：产品经理 / 功能完整性
- 现象：HANDOFF 明示手机 Tailscale 未登录（N04 遗留），无 USB 真机项只能算 PARTIAL；`adb reverse` 仍在日常使用。产品目标是"Android 可配置服务地址、脱离 USB"，这是从开发工具走向"本人日常产品"的分水岭。
- 建议：把"Tailscale 登录 + 拔 USB 走全链 + 清 reverse"列为下一个用户在场动作的单一清单项（避免每步打断用户）；完成前 UI 内可显示当前连接方式（USB 调试/私网）让用户知情。

**R1-P2-03 聊天页引导文案未区分 mock 与真实模式**
- 视角：普通用户 / 一致性 / 期望管理
- 现象：聊天页空态写"说一句之后，这里固定给一条接话和一条追问"——这是 mock/模板层行为的准确描述；但接通真实 AI（DeepSeek）后行为是模型生成，文案若不变会误导用户对能力边界的预期（建议层也有 BM25 检索 ≠ 大模型语义理解的既定红线）。
- 建议：按 `S.asrState` / AI 接通状态切换一句说明（模板演示 vs 真实模型），与现有「字幕已接入」状态行同一体系。

### P3（4 项）

**R1-P3-01 公开 PWA「Want to go」按钮触控目标偏小**
- 实测高 37px（< 44px 推荐），且与卡片打开区域相邻，密集列表易误触。建议加高至 ≥44px 或扩大热区。

**R1-P3-02 `discard` 使用原生 `confirm()`**
- 与自定义 modal/toast 体系不一致，且绕过 `t()` 文案国际化。建议统一走自定义确认弹窗。

**R1-P3-03 海南地点计数口径差异无说明**
- Web 端恒 115，Android 端 116（私有地点 `pv-hongcheng-lake-park`）。这是设计使然（私有地点不进 Web），但同一用户跨端看到不同计数时无任何解释。建议在 Android 私有地点卡上标注「仅本机」角标即可，不必动 Web。

**R1-P3-04 公开 PWA 详情页无显式「返回」控件**
- 依赖「Browse all 115」与浏览器返回；系统返回手势/物理键可用，故仅低优先级。若加，放左上角与 brand 同行。

### Future（3 项）

**R1-F-01 清单回发链路的端到端实测**：`?selected=` 生成→另一设备回显→「Send list to SocialMate」真实送达，是 PWA-03 验收的核心故事，值得一次真机双设备实测（本轮仅验证了 UI 结构存在）。

**R1-F-02 私有地点（116 类）模式产品化**：红城湖验证了"私有地点进海南列表"的机制，未来可考虑给用户一个"我的地点"管理入口（新增/编辑/导出），把单点 hack 变成能力。

**R1-F-03 TTS/Polly 与朗读体验**：后端已就绪（5 声线 + 缓存 + 独立账本），等密钥授权后做一次真人试听 Human Gate；朗读场景（练习跟读）是"外语社交"定位下最有差异化的方向。

## 3. 值得保持的优点（防倒退清单）

- 公开 PWA 隐私隔离执行到位：公开包 0 私有数据泄漏、页脚隐私声明、默认英文、零登录零上传——与 Product Plan §0-B 的"严禁"清单逐条对得上。
- 空态全部带行动指引（人物/收藏/聊天），不是空白占位。
- 设置页「即时预览 + 恢复默认」是同类项目少见的完整度。
- 三层同意（录音/留存/AI）与「spk_N 待确认」「MOCK 不是 ASR」等文案口径在 UI 与红线文档间一致。
- 数据诚实：所有"未同步/草稿/待确认"状态都明示，没有冒称。

## 4. 本轮边界与未验证项

- 未实测：Android 真机走查、录音→ASR→AI 全链（预算与设备约束）、Copy list/Send list 真实分享行为、`?selected=` 回显、iPhone Safari、深色模式视觉细节（仅验证可切换）。
- 本轮**未修改任何业务代码**；唯一产出为本文件。

### P2（2 项）

**R2-P2-01 主服务 UI 字号全面低于全局界面规范**
- 视角：普通用户 / 信息可读性 / 规范一致性
- 实测证据：侧栏导航按钮 13.5px、页脚与「数据仅保存在本机」状态说明 12px、正文 p/li 16px、h2 21px；对照全局硬性下限（正文 ≥19px / 辅助 ≥15px / 标题 ≥23px / 绝对下限 ≥14px）**四类文本全部越线**，其中页脚 12px 低于绝对下限 20%。
- 影响：4173 主服务是 README 面向用户的正式产品本体；12–13.5px 的导航与状态文本在桌面已偏小，375px 手机视口下（px 值不变）进一步压缩可读性；「数据仅保存在本机」是隐私信任文案，恰恰是最不该难读的字。
- 建议：一次性上调 CSS 字号基线（`:root` 变量集中改），优先处理 ≤14px 的三处（页脚、侧栏状态、导航按钮）；不必逐页动布局。

**R2-P2-02 话题「上次阅读」记忆不完整：会话内不记滚动位置、跨会话全丢**
- 视角：高频用户 / 操作效率 / 承诺一致性
- 实测证据：滚动至话题内 800px 刷新 → `scrollY=0`；`sessionStorage['sm-topic']` 只存话题路径；sessionStorage 关闭标签即清空。README 明确承诺「并记住上次读到的话题」。
- 影响：话题库是本产品核心高频页；用户每次回来都要重新找话题、找位置，产品承诺与体验脱节。
- 建议：`sm-topic` 迁移到 `localStorage`（跨会话恢复话题选择）+ 追加滚动位置字段（会话内刷新恢复）。两处小改，均在 `public/index.html` 话题渲染层。
