# 转发踩坑与提速清单

- 适用：`docs/relay/DESKTOP_GPT_START_HERE.md` 的“转发”执行
- 版本：v1.0 ｜ 2026-11-01 ｜ 依据：SM-ALW001-20261101-N02 实发过程
- 用法：规则每轮现读；本清单只记**判据**与**已证伪的路**，避免重复试错。

## 一、三条硬判据（其余都不要凭感觉）

1. **唯一目标 = 工作区名与实际项目根同 `target_project`。** 名字像、别的项目在跑都不算数。
2. **发送按钮从 `disabled` 变为可点 = 输入被 App 接受。** 界面上/AX 树里有文字不算数（Electron 富文本会把 AX 写入显示出来，但内部状态仍为空）。
3. **已发送 = 聊天历史出现该消息气泡 + 出现「停止」按钮/运行态。** 只有其中一项不算。

## 二、已证伪的路径（不要在旧会话上重试）

对 WorkBuddy 已完成会话「继续推进开发任务」的输入框，以下全部无效：

| 手段 | 现象 |
|---|---|
| AX `set_value` | 值变了，发送按钮仍 disabled |
| AX `type_text`（带/不带 element_id） | 值不变或仅短暂显示，按钮仍 disabled |
| 坐标点击后键入、双击聚焦后键入 | 同上 |
| Tab 聚焦、Enter、Cmd+Enter | 无反应 |
| 直接点发送按钮（元素 id 与坐标两种） | 无反应（按钮真禁用） |
| 菜单「编辑 → 全选 / 剪切 / 粘贴」 | 无任何变化，说明编辑器未聚焦 |
| 同窗口原生搜索框键入 | **成功** → 证明键盘通道正常，阻塞点在富文本编辑器本身 |

判据：**同一会话试 1 次（写入后看发送按钮）仍 disabled → 立刻判该会话输入不可用，转新会话，不换第 2 种手法。**

## 三、已验证可走通的路（照抄）

1. 点「新建任务」（约 4 秒）。
2. 打开「选择工作空间」→ 点 `alw-001-外语社交系统`（不要用「新建工作空间」）。
3. 点击新会话输入框 → `type_text` 写入 `send_text` 单行（本次一次成功，按钮即刻由 disabled 变可点）。
4. 点「发送」→ 确认消息气泡出现、出现「停止」按钮、顶部出现执行卡 → 写回执。

## 四、提速要点

- 每轮开头并行读三件：规则版本、`CURRENT_TASK.md`、`receipts/<task_id>.md`。
- 截图只截一次用于定位坐标；能用元素 id 就别用坐标（截图是缩放图，按像素直算会点偏）。
- `type_text` 单次约 19–40 秒，不要串行试十几种手段，合并成一次调用。
- 忙闲判定只看**已选中的唯一目标**；其他工具忙碌、其他项目待审批一律不影响。
- 发送成功后 30 秒内写回执收工；不等待开发者完成开发。

## 五、本次事故时间线（供复盘）

- 旧会话反复试输入 → 十余次调用全部失败（最大时间黑洞）。
- 误用 V1.3 的长文案与固定 CodeArts 判断 → 两轮无效等待。
- 最终以“新任务 + 同一工作区 + 单行 send_text”在 1 次尝试内发送成功（证据见 `receipts/SM-ALW001-20261101-N02.md`）。
