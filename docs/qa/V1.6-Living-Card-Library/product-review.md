## 二、P0（阻断交付）

### P0-1 图片上传成功，但在列表和详情里看不到（假成功）

- **问题**：私有地点/软件卡上传的图片写入 `media[]` 与 `coverMediaId`（`:3916-3926`、`:3940-3942`），但列表渲染完全没有消费这两个字段：`placeCard` 固定拼公开图路径 `/v12/img/<city>/<id3>/01.webp`（`:967`），私有 id（`c-xxxx`/`pv-xxxx`）该路径必然 404，随后走首字占位；`appCard` 根本不渲染图片（`:952`）。详情页对私有卡片只追加「编辑 / 删除」两个按钮（`:4212-4214`），也不渲染 `cardMedia`。
- **证据**：`V1.1-baseline.html:952`、`:967`、`:3913-3943`、`:4212-4214`；`12-self-list.png`；`01-home.png`。
- **影响**：用户按验收路径「新建 → 保存 → 再次编辑 → 加图」完成后回到列表，看不到自己刚加的照片，会判为上传失败并重复上传。图片这条 MVP 卖点事实上不可见。
- **修复建议**：卡片渲染时若 `coverMediaId` 存在，通过 `smCardMediaUrl()` 取私有 blob 显示封面缩略图（80–108px）；详情页增加图片区与「查看大图」；列表缺图仍用现有首字占位，不出现灰块。

### P0-2 「关于我」详情有两套编辑入口，旧入口只写 localStorage，修改会被静默回滚

- **问题**：服务端卡片详情同时渲染 `detailActions`（新 `card-edit`）和旧的「编辑这段话」按钮（`:1920`）。旧入口 `editStory` 只读改 `SAV.stories`（`:1986`），保存走 `savestory` 分支仅 `persist()` 写 localStorage（`:2040`）。而每次 `smCardsLoad` 都会用服务端数据重建 `SAV.stories`，先剔除全部 `smCard` 项（`:3937-3943`），本地改动因此被丢弃。
- **证据**：`V1.1-baseline.html:1920`、`:1986`、`:2040`、`:3913-3943`、`:4212-4214`。
- **影响**：用户点「编辑这段话」→ 改内容 → 提示「已保存」→ 重新进入页面内容回滚。属于静默数据丢失，且与「保存成功才关闭」的合同相冲突。
- **修复建议**：`smCardById(kind,id)` 命中时隐藏旧「编辑这段话」，只保留 `card-edit`；旧入口仅对纯本地种子故事开放。两种保存路径都要显式提示落点（本机 / Mac）。

### P0-3 卡片分享能力缺失

- **问题**：SPEC C 与 CHAT-01 要求把中文、英文、图片、链接通过现有手机分享通道发出。当前详情页按钮只有「复制英文」「加入聊天参考」（`:1919`），没有 `navigator.share`、没有原生 share 桥、没有分享卡。
- **证据**：`V1.1-baseline.html:1919`；全文 `navigator.share` 仅 `:4621`（GPT prompt）；`qa/FINAL-REPORT.md:37` 自述未完成。
- **影响**：README 的核心用户路径「聊天关联/分享」不成立；用户只能复制英文，图片与中文无法一次带出。
- **修复建议**：详情页增加「分享」主按钮（Web Share API + 原生桥兜底），可选中文/英文/图片/链接；分享后返回录音不重置；在聊天推荐里同样给出分享入口。

## 三、P1（应在交付前修复）

### P1-1 字号全线低于全局硬下限

- **问题**：CSS 变量实测值低于「正文 ≥19px、其他正文类 ≥15px、标题 ≥23px、任何文本 ≥14px」：
  - 正文 `--reading-body:16px`、英文 `--reading-en:18px`、辅助 `--reading-meta:14px`（`:80`）
  - 卡片正文 16px（`:105`）、英文 18px（`:106`）
  - 表单标签/按钮/meta 14px（`:108`、`:109`）
  - 移动端页面标题 20px（`:5`）
  - 底部 Tab 文字 11.5px（`!important`，`:291`）
  - 补充覆盖 `--fs-meta:14px`、`--fs-body:17px`（`:295-297`）
  - `.n05controls .n05mini` 12px（`:585`）
- **证据**：`socialmate-v1.2/source/V1.1-baseline.html:80`、`:105`、`:106`、`:108`、`:109`、`:5`、`:291-297`、`:585`；构建产物 `socialmate-v1.2/index.html:80`、`:295` 同值。
- **影响**：中文正文与英文都偏小一档；按钮/表单标签属「其他正文类」却只有 14px；底部导航 11.5px 是明确违规。
- **修复建议**：把 `--reading-body` 提到 19px、`--reading-en` 不低于 19px、`--reading-meta` 提到 15px（纯元信息可保留 14px 但不要再用于按钮/表单标签）；移动端 `.top h1` 与卡片标题 ≥23px；底部 Tab ≥14px；删除 `<14px` 的散点。

### P1-2 首屏密度与「内容优先」未达标

- **问题**：关于我顶部常驻「＋ 新增 / 回收站 / 同步到本机档案」三个按钮，在 393 宽下换行，叠加分类、计数、「仅本机草稿 · 未同步 Mac」，首卡推到约 40% 处；软件页一屏只能放 1 张完整卡片，第二张被截断。
- **证据**：`12-self-list.png`、`01-home.png`；`V1.1-baseline.html:972`（同步按钮与新建/回收站同排）、`:5`、`:41`（海南移动端图片 190px）。
- **影响**：用户首屏看到的是操作按钮与状态文案，而不是「可扫视、可当场开口」的内容；与 README「首屏内容优先，禁止大说明/大空白」直接冲突。
- **修复建议**：把「同步到本机档案」移入低频菜单或详情；三个新建按钮统一为「＋ 新建」；列表顶部压缩到搜索+分类两行；软件卡片改「小图标 + 名称 + 一句话中文用途 + 类型标签」，英文全文留详情。

### P1-3 软件作品卡片没有图标/封面，且整段英文灌入卡片

- **问题**：`appCard` 只输出编号、分类、名称、完整英文 `en` 与步骤数（`:952`），没有封面图，也没有一句中文用途；由于 `.card p` 的行数限制被覆盖（`:107`），长英文在卡片里完整铺开。
- **证据**：`V1.1-baseline.html:952`、`:107`；`qa/01-home.png`。
- **影响**：一屏 1 张卡、信息密度极大、中文用户阅读成本高；与 SPEC B「软件图标或封面 + 软件名 + 一句话用途 + 类型/标签」不符。
- **修复建议**：卡片改为图标/封面 + 中文名 + 一句中文用途 + 类型标签；英文简介进详情；私有卡片同样用 `coverMediaId`。

### P1-4 新建/编辑表单校验与关闭行为不满足合同

- **问题**：保存只校验「中文或英文至少写一项」（`:4054`），标题可以为空；没有「有未保存修改」提示；点「取消」直接关弹层（`:4020`、`:2040`）；没有重复标题提示。
- **证据**：`V1.1-baseline.html:4013-4022`、`:4050-4055`、`:2040`。
- **影响**：可产生无标题卡片；误触关闭丢草稿；同名卡片被静默建成两条。
- **修复建议**：标题必填；关闭前检测 dirty 并二次确认；标题重复给提示并提供「继续新建 / 打开已有」。

### P1-5 AI 生成英文的付费同意闸被绕过，且把成本显示给用户

- **问题**：请求体写死 `consent:true`（`:4177`），只要点按钮就直接调用付费接口；按钮下方提示「AI 生成中…（约 0.0003–0.001 元）」把内部计价暴露给最终用户。
- **证据**：`V1.1-baseline.html:4176-4177`。
- **影响**：违反 README/SPEC「按需点、默认不自动调用付费 API」「保持既有同意闸」；价格显示属开发话术。
- **修复建议**：接既有 consent 状态（首次弹一次确认并记住），移除价格提示，只保留「生成中 / 已填入草稿，请核对」。

### P1-6 图片管理缺排序、新建无入口、删除不可恢复

- **问题**：图片区只有「设为封面 / 删除」（`:3993-3996`），无排序或拖拽；新建表单不显示图片区（`:4024` 仅在 `c.id` 存在时渲染）；`deleteMedia` 直接 `fs.rm` 物理删除（`private-cards.mjs:374-383`），无回收站。
- **证据**：`V1.1-baseline.html:3991-3999`、`:4024`；`private-cards.mjs:374-383`。
- **影响**：SPEC「设封面/移除/更换顺序」「删除与恢复」未满足；误删照片不可逆。
- **修复建议**：新增上移/下移或拖拽排序；新建表单先给图片区（或保存后自动进入编辑并聚焦图片区）；媒体删除先软删。

### P1-7 「仅本机草稿 · 未同步 Mac」对所有卡片无条件显示，状态错误

- **问题**：列表标题下固定输出 `self.localOnly`（`:972`），每张卡片 meta 也固定输出 `self.draftTag`（`:971`）；即便是已写入服务端 `PrivateCards` 的卡片，也显示「仅本机草稿 · 未同步 Mac」。
- **证据**：`V1.1-baseline.html:630`、`:971-972`；`qa/12-self-list.png`（新卡同样带该标签）。
- **影响**：用户无法判断哪些内容已落 Mac、哪些仅在本机，直接影响「备份/跨端一致性」的信任。
- **修复建议**：按来源字段（`origin/source`）分别渲染「已在 Mac 私有库 / 仅本机草稿」；顶部状态行改为动态统计。

### P1-8 空结果没有新建入口

- **问题**：三页空态都只是一句提示，无「新建」按钮（`:619`、`:625`、`:1916`）。
- **证据**：`V1.1-baseline.html:619`、`:625`、`:1916`。
- **影响**：TAG-01「无结果有简洁新建入口」未满足；用户搜不到时只能回顶部找按钮。
- **修复建议**：空态内嵌「用这个关键词新建一条」按钮，带入当前搜索词。

### P1-9 新建按钮命名不一致

- **问题**：关于我是「＋ 新增」（`:629`、`:972`），海南是「＋ 新建地点」（`:954`），软件是「＋ 新建作品」（`:953`）；SPEC/README 要求统一「＋ 新建」。
- **证据**：`V1.1-baseline.html:629`、`:953-954`、`:972`；`qa/12-self-list.png` OCR 为「+ 新增」。
- **影响**：三页操作模式号称统一，但主操作文案不一致，用户需要重新识别。
- **修复建议**：统一为「＋ 新建」，类别说明放到弹层标题（新建地点/新建关于我/新建作品）。

### P1-10 主题默认值为 light，而非 SYSTEM

- **问题**：`SAV.theme??='light'`（`:934`），设置页提示「默认浅色」（`:643`）；全局规范要求默认 `SYSTEM`。
- **证据**：`V1.1-baseline.html:934`、`:643-644`；深色 CSS 本身齐全（`:2`）。
- **影响**：系统深色用户首次进入仍是浅色；V1.6 没有改这一点。
- **修复建议**：默认 `system`，首次运行跟随 `prefers-color-scheme`；保留用户手动选择并持久化。

## 四、P2（可排期）

### P2-1 开发话术/内部标识直出

- 「不会发布到公开 **PWA**」（`:4010`）、「**中文真源**；AI 只生成英文草稿」（`:4017`）、`SocialMate-Data/Profile`（`:632`）、「约 0.0003–0.001 元」（`:4176`）、软件卡片的 `P002` 编号（`:952`，`01-home.png`）。
- **影响**：与 SPEC「禁止开发阶段标签/技术字段」冲突；P 编号对用户无意义。
- **建议**：改成用户语言（「照片只保存在你自己的手机和家里的小服务器上」）或隐藏内部字段。

### P2-2 海南卡片图片高度超出规格

- 移动端 `.placecard .thumbwrap{height:190px}`（`:41`），SPEC 建议 80–108px。单卡高度变大，直接压缩首屏内容量。
- **建议**：移动端回到 96–108px，点击详情再放大。

## 七、流程顺畅性

按「新建 → 保存 → 再次编辑 → 加图 → 删除 → 恢复」走查：

1. **新建**：列表主按钮可直达弹层；三页入口位置不完全一致（关于我在搜索行内，海南/软件在搜索行上方）。
2. **保存**：按钮 sticky 可见（`13` 证明）；未保存关闭无确认（P1-4）。
3. **再次编辑**：卡点详情 → 「编辑」可用；但关于我另有「编辑这段话」会写错落点（P0-2）。
4. **加图**：新建态没有图片区，必须先保存再编辑（P1-6）；上传后列表与详情都不显示（P0-1），用户会认为失败。
5. **删除**：详情「删除」→ 页内二次确认抽屉（`:4131-4135`），符合「不用 window.confirm」的既有约束。
6. **恢复**：列表「回收站」→ 恢复（`:4145-4167`），链路可用；照片不会随恢复丢失，但单张图删除不可恢复（P1-6）。

**必须滚动才看到按钮**：表单主按钮不用滚动（sticky）；但「状态/说明」在按钮下方，需要滚动。**弹层关闭后找不到入口**：未复现，列表主按钮常驻。
