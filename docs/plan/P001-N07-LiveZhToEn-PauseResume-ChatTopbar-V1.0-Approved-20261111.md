## 0. 用户实际使用场景（不可误解）

用户与外国朋友**面对面交流**，已开始录音与实时同传。朋友说英语，用户通常也说英语；突然遇到不知道怎么表达的句子，用户直接说中文，字幕把原中文识别进去；用户点击顶部**「译英」**，**屏幕紧接相应中文显示一条自然口语化英文**，用户看着手机**亲口用英文说出来**，随后正常继续对话。

**绝对不要做**聊天消息发送、复制后发送、自动向对方推送内容、实时麦克风外放英语、强制输入框/发送框或「中文／英文模式切换」。本功能是**仅供本人读的现场口语提示**，不是文字聊天 APP。

中文/英文**自动混合识别**，用户无需手动切换语种；「译英」只是**主动触发**最新用户中文定稿句的翻译，绝非中英识别模式开关。翻译不抢占麦克风、不停止腾讯 ASR、不打断接话/追问/分享与点词查询；不自动逐句扣费。

第二典型场景：朋友去上厕所或临时离开十分钟——用户点**「暂停」**，麦克风停止采集/传输；朋友回来点**「继续」**，继续**同一轮聊天 Session**，所有录音片段/字幕仍归属同一应用层会话；真正告别才「结束本轮」并转记录与复盘。

## 2. P0-A｜录音过程中按需把自己的中文译成英文

### 2.1 明确交互

1. 用户在录音中说出中文；同一轮字幕立即按原逻辑追加中文 **final**，保留说话人、原文及时间顺序。
2. 顶部设一个清晰的**「译英」**按钮；点击后只翻译**最后一条被可靠判定为「我」且包含中文的 final 字幕**。若说话人不明或最新中文属于朋友，不得自动猜选错人：可点击目标中文句子后再按「译英」，或在极轻量候选菜单中显式选择。
3. 向既有 `/api/ai/draft-en` 请求该句已确认的中文（非不断变化的 interim），沿用已配置 DeepSeek、授权头 `x-archive-token`、预算闸、失败提示。
4. 把译文以**同一字幕下方**的一行/两行明显但紧凑的英文显示，仍能看清原中文。只生成**一个**最自然、简单、朋友之间常说的英文版本，避免机器味和三版难度切换。示例：`我想下次跟你一起去试试。` → `I'd love to give it a try with you sometime.`
5. 用户直接照着念，不需要「复制」「发送」「输入」「朗读」按钮，也不自动把英文当作真人说过的话写成另一句 ASR 消息。
6. 对中文译文与原 ASR final 建立可追溯关联（同一 messageId/源文快照），不覆盖中文、消息顺序、录音原始归档；翻译失败可重试，已成功同一 messageId 防连点、重复请求和重复计费。
7. 支持译英期间 ASR 继续写入其他 final：**结果必须回填到触发时的原目标消息**，不能被后来的朋友字幕挤到错误气泡里。原译英正在运行时按钮可显示「翻译中…」，不要求阻塞整个录音界面。
8. 若本轮中还没有中文 final，按钮给轻量「先说一句中文」反馈而不计费。避免把英文字幕送入 `draft-en` 装作翻译。
9. 如果模型/网络/预算不可用，原中文仍完整显示，给明确短提示，允许稍后重试，不影响录音/字幕。

### 2.2 网络与敏感数据

- 在 OPPO 蜂窝 5G、Wi-Fi OFF、无 Mac 可达时，优先现有 Android direct DeepSeek 路由。不能默认手机一定连 Mac；不新增云端网关/数据库。
- 查询仅发送用户**主动选中的中文句子**与最低限度的必要短上下文；不额外批量上传整轮人物档案或未经请求的历史会话。复用既有 Key、预算与记录策略，不能把 API Key、语音原文写入公开日志。

## 3. P0-B｜把「暂停」与「结束本轮」真正分开

定义一个小而明确的应用层状态机：

| 状态 | 主操作 | 麦克风/ASR | 会话与字幕 |
|---|---|---|---|
| `IDLE` 未开始 | **开始** | 尚未采集 | 准备创建本轮 |
| `RECORDING` 录音中 | **暂停** | 连续采集并实时识别 | 每句 final 追加到本轮 |
| `PAUSED` 已暂停 | **继续** | **停止采集和发送麦克风音频**、停止应计 ASR 时长（按真实供应商账单核对） | 本轮 Session、字幕和接话上下文原样保留 |
| `FINISHED` 本轮结束 | 下一轮「开始」 | 停止采集 | 本轮封存，人工确认/复盘 |

- 一轮对话允许 **多次暂停/继续**；例如 14:00–14:20 录音，14:20–14:30 暂停，14:30–15:00 继续，最后是一条 14:00–15:00 会话，内含 2 段有效采音片段。暂停期间不产生伪造空白字幕。
- 暂停时先确保**已接收或正在生成的最终字幕不丢**：排空已确认 final/处理在途结果，关闭或挂起本机音频采集以及 ASR 传输，释放麦克风占用；必要时供应商 WS 会话结束、继续时另建 WS，但复用原**应用层逻辑 Session ID** 并关联多个底层片段。不得声称腾讯底层连接 ID 一定原封不变。
- 继续时从现有位置继续追加，字幕原文与人物关联/允许留存状态不清空、不重复生成新的会话头、不把前一段重复归档；恢复失败保持 `PAUSED` 并可再点继续，不能显示已经恢复而后台无录音。
- **结束本轮**是明确操作，不要偷偷作为暂停按钮行为；放在顶部「···」低频菜单，点击后采用现有结束/人工确认/放弃原流程，必要时给简短确认。结束后不能无提示恢复已经封存会话。
- 录音过程中允许「译英」；暂停时用户可查看已生成的字幕及译英结果，若从暂停状态主动对已确认中文译英，不允许暗中恢复采音。
- 处理原生 Android `AsrActivity` 实际停止、前后台/切网及 `smNativeRecordingStopped` 的状态回调。暂停必须是**真实麦克风停止采集**，不能只让 UI 显示“已暂停”；录音状态与费用/时长显示应一致。
- 不新增复杂录音服务器、永久后台服务、自动长时间监听或新的隐私默认值；沿用既有录音前明确告知与保存授权。暂停/继续真实可用之前不能标 PASS。
