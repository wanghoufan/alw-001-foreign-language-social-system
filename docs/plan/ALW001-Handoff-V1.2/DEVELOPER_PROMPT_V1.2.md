## 1. 不允许擅自变更的界面与交互规则（验收红线）

1. **五个底部主 Tab 不变**：「软件」「海南」「聊天」「关于我」「人物」。手机固定底部栏；桌面左侧栏；默认浅色、支持深色。每个 Tab 专注一项主任务，不重复添加跨 Tab 的功能卡入口。
2. **聊天页的主要布局不变**：对话原文区 + AI 自动接话区 + 自动关联资料卡；手机纵向排列，保持一眼可看到演示启动/核心操作；桌面可分栏。保留原始话语与说话人来源，不让模型改写原文。
3. **自动内容为第一优先级**：每当收到稳定 ASR 最终句（演示用手动输入替代），AI 判断话题/上下文并自动更新：① 一句自然接话；② 2–3 句前后连贯、可继续追问的英语；③ 一句可用来分享自身生活经历的英语；④ 2–4 张已有数据来源的关联卡。用户不用搜索、不用点「查资料」才能出现。
4. **户外跑步是必过验收用例**：对方说 `I like running outdoors near the sea. Is there a nice park or running route in Haikou?`，页面必须自动弹出自然的接话/连续追问，并自动关联正式海南库里的 **万绿园 NO.39、海口湾滨海步道 NO.41、白沙门公园 NO.45**。不能只有机械关键词列表、不能只有一条与上下文无关的泛泛追问。
5. **资料卡可穿透**：点击自动卡片 → 跳到已有的「海南」/「软件」/「关于我」对应详情，展示源原文的中英双语介绍；地点提供 Google/高德地图与复制、分享；有明确「返回聊天」，且原会话、说话人和上下文不会丢失。不得跳到空白页、搜索结果页或不存在的链接。
6. **手动检索是备用入口**：默认折叠、不抢占推荐卡位置；用户展开才使用。此前用户截图里“快速查资料”占据重要空间是被明确否决的布局，不得恢复为默认主功能。
7. **软件主稿必须唯一**：`docs/成果整理/2026-10-31 - Mac Mini - ChatGPT - Bilingual Software Portfolio-Demo Guide - V1.4.md` 的 51 项正式作品和 204 个步骤，手机 APP / PWA 排最前，不能偷换为 `temp/intros-A～I` 草稿；每个软件保留原 P ID、步骤顺序和自然英文。
8. **地点源必须完整**：`docs/成果整理/Hainan-Travel-Guide/baseline/places.json` 的 115 条真实地点。随包便携 HTML 仅示例 23 条，严禁把这 23 条当作正式完成的数据库。检索卡须保留 id、双语原文、来源、地图链接。未确权图片不能公开分发。
9. **人物档案需审阅**：先保留原始转写，再人工核对谁说的与具体事实；确认后才通过既有 preview→apply 写入私人档案。个人隐私/聊天录音/模型秘钥不得进入公开海南 PWA。
10. **真实技术接入不能改变交互契约**：BOYA mini 当前按混音处理，Android 原生采集，腾讯云 ASR 在服务端接入；说话人来源无法确认时明确标记“待确认”。真实 AI 提问要能上下文延续、避免重复与生硬模板；带上来源引用，无法确认时不得编造地点/事实。允许调整内层实现、服务接口、容错，但**未经用户亲自看到并确认，不允许改变原型核心布局、五 Tab、卡片入口、自动推荐优先级、复制/分享和返回操作**。

## 2. 开发执行：不要因为真人录音和云凭据缺失而停工

- 先对照 HTML 逐屏落实，明确现有 `socialmate-prototype/` 与随包 HTML 的差异：随包 HTML 是本次用户直接看过并反馈后修订的交互基线，若 Mac 版仍有差异，按 UI 契约修订正式 HTML，再回归。**不要覆盖其他智能体同时在改的文件；协商目录 owner，保留未提交修改，不 reset/clean。**
- 既有 Android 音频与 ASR Bridge 优先保持独立模块。不需要重写已能工作的部分，先完成一个可回退的 UI 接线层（Mock ASR / 离线转写事件驱动）。
- 实现会话上下文保留、话题状态、自动资料召回、来源溯源、跨 Tab 详情与返回、收藏、分享、会后预览确认；形成清晰状态图。话题推荐不必仅靠正则词匹配：正式服务可使用轻量 LLM + 检索，设去重、相关性、跨轮上下文和超时/无 Key 降级。
- 模型/API 无密钥时继续完成无依赖功能、演示/mock 通道、真正的脚本构建和自动化回归；真实腾讯云账号、外网权限及用户双麦真人 QA 只留给最终外部验收环节集中提一次，不中断其余开发。
- 使用真实 V1.4 + 海南 115 正式资料，不能因为 HTML 便携版数据少就删除其他内容。没有真实证据的功能保留「待核实」标识；不要杜撰生产部署状态。

## 3. 验收必须“原型对照 + 真操作”，不能只看自动化 PASS

A. 静态：私有页面五 Tab、浅色默认/深色、手机 360/390/412/430、横屏/桌面、主任务占首屏、输入法遮挡、无横向溢出。

B. 数据：51 款软件和 204 步、海南 115 地点、P 编号/地点 ID 保留、完整双语和地图、公开与私人数据隔离。

C. 自动推荐（至少 5 话题回归）：户外跑步→上述三个真实地点、咖啡→自身拿铁经历、做软件→作品集、海边→海南地点、其他日常→自然追问但不强推无关地点。每次都应：无需搜索触发；接话自然；追问会延续；2–4 张来源卡；打开详情/返回不丢会话；可复制与分享。

D. 会话：没有录音权限时仍可离线浏览；ASR 模拟与真实转写显式区分；人审后才入档；未知说话人不得强行绑定人物；不会把私人信息发到公开分享页。

E. 自动化和视觉：运行 `node --test socialmate-prototype/test-prototype.cjs` 与 `bash socialmate-prototype/verify-and-package.sh`，再用真实浏览器开 HTML，至少提交「聊天前/户外跑步建议出现/推荐卡展开/返回聊天/五 Tab」的截图和真点击证据。测试失败自行修复重测。小米/红米/OPPO 原生浏览器是后续真机必测，不能只在 Chrome 通过就标记正式交付。

## 4. 交付内容与结论规则

交付时给出：正式 HTML 文件地址、可下载 ZIP、真实截图、测试日志、数据计数、主要差异对照、所有 Bug 处理记录、APK/ASR 接线进展、仍需用户操作的事项。状态分为 `HTML 交互通过`、`Mock 链路通过`、`腾讯 ASR 实测通过`、`红米/博雅真机通过`，不得混淆。

**最重要的验收一句话：如果用户说“户外跑步”，不应该首先让他看见搜索框；应该自动出现「怎么接话/下一句问什么/能分享什么/可以打开的真实海南地点卡片」。**
