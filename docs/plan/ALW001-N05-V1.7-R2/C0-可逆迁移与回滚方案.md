## 二、origin 数据导出顺序（不可颠倒）

按"越易失、越不可再生，越先导出"排序：

1. **旧 WebView origin 的 localStorage 9 键**（最易失：换 origin 即隔离）
2. **sessionStorage 2 键**（令牌不导出，只导出 `sm-person`）
3. **Android `files/archive/`**（`current.json` → `outbox/` → `exported/` → `quarantine/`）
4. **Mac `SocialMate-Data/` 私有数据**（PrivateCards → People → PlaceNotes → PrivatePlaces → ManualFactBatches → Favorites → Profile → Prefs → LearningArchive → Demo 单列）
5. **Mac TTS 缓存与账本**（`TtsCache/` + `ledger/doubao.json` + `.local/asr-budget.json` + `.local/ai-budget.json`）
6. **公开种子**（`source/places-115.json` + `docs/成果整理/Hainan-Travel-Guide/images`）：可再生，最后导出

导出脚本要求：

- 只读：不得在原 origin 写入、删除、`clear()`。
- 每个文件带 `sha256` 与 `bytes`；生成 `manifest.json`。
- localStorage 导出后立刻做"键数=9、JSON 可解析、无令牌"三项断言。
- 导出包默认加密（用户口令），令牌与 Keystore 内容永不入包。

## 三、升级路径 A：旧 0.9.1/vc69 → 新包覆盖安装

### A1. 准备

1. 完成第一节 P1–P12。
2. 新包 versionCode 必须 > 69、versionName 明确（例如 1.0.0/vc70），签名与旧包一致。
3. 新包保留同一 `applicationId`，否则不是"覆盖安装"而是并存/新装。

### A2. 覆盖安装（不卸载）

```bash
adb -s <serial> install -r <new.apk>
```

- `-r` 保留 `/data/data/app.socialmate.dualmic/`（含 `files/archive`、SharedPreferences）。
- 安装后先 `am start -n app.socialmate.dualmic/.MainActivity`，截图确认前台是新包。
- 首启动**不得**立刻清旧 origin 数据；先进入迁移页/迁移任务。

### A3. 首次迁移步骤

| 步骤 | 动作 | 通过判据 |
| --- | --- | --- |
| M1 | 新包读取导入包 `manifest.json`，逐项校验 sha256 | 全部匹配，否则中止 |
| M2 | 建 SQLite 库与表（schema 版本 v1），写入只读种子（DS-01/DS-02） | 115 条地点 + 图片数量与清单一致 |
| M3 | 导入 localStorage 9 键 | 键数、条数、抽样字段一致 |
| M4 | 导入 `files/archive` 索引 | sessionId 集合一致；`current.json` 不为空时先补 outbox |
| M5 | 导入 Mac 私有数据（DS-03..DS-14） | 每类条数/id 集合/revision 一致 |
| M6 | 导入 TTS 缓存索引 | 文件数、总字节、抽样可播放 |
| M7 | 建立"迁移报告"页：每类成功/失败/跳过 + 原因 | 用户可读，可导出 |
| M8 | 双读核对（本地 vs 旧 Mac 接口） | 差异清单为空，或差异已逐条确认 |
| M9 | 切写 LOCAL | 新写入只落本地；旧接口降为只读 |
| M10 | 再次导出"迁移后快照" | 与 M3–M6 计数一致 |

> M9 之前，任何"保存成功"都必须写旧真源或明确标为"待迁移草稿"，不得出现"看似保存、实际两边都没有"。

## 四、清空重装恢复路径 B（新手机 / 卸载后重装）

1. 在新设备安装同签名新包（versionCode > 69）。
2. 首次启动进入"从备份恢复"，选择加密备份包。
3. 校验包口令、`manifest.json`、sha256。
4. 先恢复只读种子，再恢复私人数据，最后恢复 TTS 缓存（缓存可缺，缺了标"未缓存"）。
5. 恢复后执行与 A3-M8 相同的双读核对（本机无旧 Mac 时，改为"条数/哈希/抽样"三重核对）。
6. **不恢复**：`sm-archive-token`、Keystore 私钥、设备配对令牌；需重新配对。
7. 恢复完成前不得让页面进入可写状态。

## 五、旧包保留与回滚条件

### 5.1 保留物

| 保留物 | 位置 | 保留期 |
| --- | --- | --- |
| 旧 APK（0.9.1/vc69） | `artifacts/` 或 `release/` 固定路径 | 至少到 V1.7 验收通过 |
| 旧包数据快照 | 项目内 `artifacts/migration/`（加密） | 至少 2 个版本周期 |
| 迁移前 manifest + sha256 | 同上 | 同上 |
| 迁移报告 | 同上 | 同上 |

### 5.2 回滚触发条件（任一成立即回滚）

1. M1/M5 校验失败且无法在 24 小时内定位。
2. 新包冷启动无法进入五 Tab（只出现连接页/只读面板）。
3. 私人数据条数或 id 集合缺失超过 0 条（不允许"差不多"）。
4. 媒体文件缺失或不可解码超过清单的 0%（图片是唯一原件时必须 0）。
5. 会话原文 `sessionId` 集合缺失 > 0，或 `outbox` 未成功接管。
6. 桥在合法页面被撤销（保存/录音/朗读任一失效）。
7. 出现"保存提示成功但本地库无记录"的任一次。

### 5.3 回滚步骤（保持可逆）

1. 先在新包内导出"回滚前快照"（新包本地库 + 媒体 + 迁移日志）。
2. 若新包与旧包同 `applicationId`：卸载新包会删除 `/data/data/...`，因此**必须先导出**；再安装旧 APK。
3. 若需保留新包数据：用不同 `applicationIdSuffix` 的临时测试包共存，不覆盖生产包。
4. 安装旧包后，用第 2 节导出包反向导入旧 origin（通过旧页面注入脚本写回 localStorage）。
5. 回滚后复跑 P1–P3，确认旧包可用，再记录回滚原因与时间。

> 不允许用 `adb shell pm clear`、`git reset/clean`、删除 `SocialMate-Data` 作为"回滚手段"。

## 六、失败判据（迁移失败的判定标准）

| 类别 | 判据 | 处理 |
| --- | --- | --- |
| 数据完整性 | 任一类条数/id 集合与 manifest 不符 | 立即停止切写，保留双源，回滚 |
| 媒体完整性 | 图片/音频 sha256 不符或无法解码 | 相同 |
| 会话原文 | `sessionId` 缺失、`outbox` 未接管、重复上传 | 相同 |
| 桥可用性 | 合法页面 `saveText/requestRecording/speakText` 任一返回 false | 相同 |
| 静默失败 | 提示成功但本地无记录 | 相同，并记为 P0 缺陷 |
| 性能误判 | 以"首页 295ms"当作离线通过 | 不算通过，必须重跑五 Tab 冷启动 |
