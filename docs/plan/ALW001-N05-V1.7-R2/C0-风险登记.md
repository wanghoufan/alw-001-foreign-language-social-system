## 一、高风险

### R-C0-01｜首屏强依赖 Mac，离线即只读面板

- **证据**：`AsrActivity.java:192` `discoverLan(900)`；`928/938/946/1046` `loadUrl(privateUiUrl())`；`870-890` `onReceivedError` → `showOfflinePanel`；无加载超时逻辑（`rg "postDelayed|TIMEOUT"` 仅命中 `1758` 的提示与 `1106-1112` 的 HTTP 超时）。
- **影响**：Mac 关机/断网时用户打不开五 Tab；与"无网络也能用"直接冲突。
- **缓解**：C1 改为 assets/local origin 首屏；C2 本地库先读后渲染；加载失败只影响外部功能，不整页只读。
- **验收方式**：Mac 断电 + 断 Wi-Fi + 拔 USB + 清 `adb reverse` 后强杀冷启动，5 Tab 可操作；`onReceivedError` 不再触发整页面板。
- **状态**：未修复。

### R-C0-02｜换 origin 后 localStorage/sessionStorage 不继承

- **证据**：`index.html:2068`（`sm-archive-token`）、`2754-2762`（`sm.privatePlaces.v1`）、`2085-2086`（`sm-people-draft`）、`3310`（`sm-n05-practice-cache`）；计划原文 A.4。
- **影响**：直接切 `appassets.androidplatform.net` 或 `file://`，用户草稿、私有地点缓存、TTS 音色选择全部"消失"；用户会认为数据丢了。
- **缓解**：按 `C0-可逆迁移与回滚方案.md` 第 2 节，在旧 origin 完成 9+2 键导出并校验后才切；导入 SQLite 后清旧键。
- **验收方式**：迁移前后键数/条数/抽样字段一致；旧键清空后新库仍可读。
- **状态**：未修复。

### R-C0-03｜私有地点双真源分裂

- **证据**：`index.html:2799` `/v12/api/private-places`；`index.html:3974`、`4125-4134` `/v12/api/cards?kind=place`；`server.mjs` 同时存在两套路由；磁盘上 `SocialMate-Data/PrivatePlaces/`（8 文件）与 `SocialMate-Data/PrivateCards/`（21 文件）并存。
- **影响**：同一地点两处修改不一致；断网缓存只覆盖 `private-places`，卡片侧改动不进入缓存，恢复后出现"旧地点回来"。
- **缓解**：迁移裁决以卡片表（有 revision/trash/restore）为主；`PrivatePlaces` 作为一次性导入源；冲突逐条人工确认。
- **验收方式**：合并后地点 id 集合唯一；同一 id 的 `updatedAt` 取较新；断网重启后显示最新值。
- **状态**：未修复。

### R-C0-04｜桥安全边界：4 个方法无方法级 origin 校验 + 配对同步阻塞

- **证据**：`AsrActivity.java:1300-1336` 仅在私有 origin 注入桥；`840-890` 离开 origin 撤桥；但 `1458 setLanguage`、`1465 isRecording`、`1471 pairDevice`、`1486 connectionMode` 方法体内无 `isPrivatePanelUrl`（对比 `1519 saveText`、`1495 requestRecording` 有）。`DevicePairing.java:93-125` `pair()` 同步 `HttpURLConnection`。
- **影响**：若 assets 化后桥注入判断放宽，外部 frame/脚本可调用这四个方法；`pairDevice` 在 JavaBridge 线程做网络请求，弱网会卡住页面 JS 调用。
- **缓解**：C1 统一桥白名单与 origin 限制（必要时 `WebMessageListener`）；四个方法补校验；`pairDevice` 改异步任务 + 明确超时。
- **验收方式**：非私有 origin 下四个方法均返回拒绝；弱网配对不阻塞 UI；`test-android-wiring.mjs` 通过。
- **状态**：未修复。

### R-C0-05｜`allowBackup=false`：无系统备份，卸载即不可恢复

- **证据**：`AndroidManifest.xml:21` `android:allowBackup="false"`；`SessionArchive.java:106-109` 数据在 `filesDir`；SharedPreferences + Keystore 均在应用私有目录。
- **影响**：换机、卸载、清除数据都会丢会话原文、配对凭证、本地库；不能依赖系统云备份"兜底"。
- **缓解**：只走"应用内导出/导入 + 局域网备份"；导出包加密；凭证独立重建。
- **验收方式**：卸载重装后仅凭备份包恢复全部条数；令牌不被带出；恢复前不可写。
- **状态**：方案已写，未实装。

### R-C0-06｜assets 化会同时打断七条主线

- **证据**：`server.mjs:1437-1441` `/profile-sync.js`、`1442-1450` `/v12` 页面、`1455-1475` `/v12/img/`、`1479-1484` `/v12/api/archive/` 均为同源路由；`index.html` 大量相对 URL（52 个模板）；`AsrActivity.java:751-759` 已禁 file/content/universalAccess，`MIXED_CONTENT_NEVER_ALLOW`。
- **影响**：只把 `index.html` 塞进 assets 会出现：相对接口 404、CSP `connect-src 'self'` 拦截、写票/归档令牌跨源、根绝对路径失效、图片 404、混合内容被拒、离线语义与"已缓存"混淆。
- **缓解**：C1 用 `WebViewAssetLoader` 提供 HTTPS origin；统一 adapter 把 `/v12/api/*`、`/api/ai/*`、`/v12/media/*` 分流到 local/cloud/LAN；CSP 随 origin 重写。
- **验收方式**：assets 首屏无 404/无 CSP 报错；每个 URL 模板走到预期目标；`console` 无 mixed content。
- **状态**：未修复。

## 三、低风险（需知悉）

### R-C0-16｜debug 包允许 WebView CDP

- **证据**：`AsrActivity.java:168-171` 仅 `FLAG_DEBUGGABLE` 时 `setWebContentsDebuggingEnabled(true)`。
- **影响**：debug 包可被本机 CDP 读取页面；release 不受影响。
- **缓解**：发布包保持非 debuggable；真机取证只用 debug。
- **验收方式**：release 包 `chrome://inspect` 不可见目标页。

### R-C0-17｜服务端路由计数口径与摘要有差

- **证据**：`rg -n "url\.pathname" server.mjs | wc -l` = 82；其中 `url.pathname===` 50 行、`.match` 24 行、`.startsWith` 2 行。摘要写"约 88 条路由"。
- **影响**：若按摘要做覆盖率统计，会低估/高估未分类路由。
- **缓解**：统一按"pathname×method 展开"重新计数并落表；C1 逐模板对账。
- **验收方式**：路由清单与前端 52 模板双向映射无遗漏。

### R-C0-18｜版本与发布状态易被夸大

- **证据**：`build.gradle:13-14` 0.9.1/69；开发报表仅 debug APK；计划原文 A.12。
