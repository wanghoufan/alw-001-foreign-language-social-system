## 1. 产品交互约束（以此为最终实施目标）

### 1.1 海南 → 红城湖 → 我的记录
1. Android 的「海南介绍」地点列表增加**私有自建地点**能力（不修改原公开 115 条）：系统合并展示“115 个公共地点 + 个人地点”，红城湖私有记录用 `private:<UUID>` 或其他**独立命名空间**，绝不复用数字 1–115。
2. 红城湖详情顶部：地点封面图、地点名称/位置/简短中英背景介绍；其下是「我的游玩记录」时间线。用户 2026-11-03 实测记录应为一条可展开的 `record`，其下按练习块划分，不把 19 段原稿打散为 19 条互不关联的记录。
3. 「记录新想法」支持大段粘贴、预览字数、自动保存草稿、AI 整理、手动改分段、人工确认和再次编辑。原文、AI 修订版和用户确认版分别保留来源与版本；失败/断网退出重进不丢稿。
4. 原有地点的公开介绍始终只读；私有地点可有用户维护的“地点介绍”与个人记录。私有地点不得意外混入 PWA/公开分享。

### 1.2 点朗读就播放：授权与播放彻底拆开
- “中文 / 英 A / 英 B / 听词组 / 循环本段”是**播放操作**，不是“先弹第三方授权窗口”。已缓存音频 → 立即播放；已获相应授权且配置、预算都有效 → 先显示小型“正在生成”状态，生成后自动播放，成功后重播直接命中缓存。
- 首次 AWS Polly 接入、地区/数据外传知情同意、额度限制等放在 **设置 → 语音与隐私 → Amazon Polly** 的**一次性配置流程**。授权应有清晰范围、撤销入口，并遵守后端真实鉴权/预算闸；如必须针对特定敏感记录独立同意，在记录层进入播放页前给明确开关，而不是点每个词都弹。
- **未配置 AWS**：按钮附近显示“云朗读未就绪，去设置配置”或标禁用，绝不继续 `consent_pending → 501` 的假交互；不能悄悄切换用户已否决的系统声音。允许用户在设置里显式选“临时系统朗读”，不作为正式质量验收。
- 播放按钮变成「播放中 / 暂停 / 重播」状态并提供停止、上一段/下一段、倍速、循环。切段后旧队列彻底停、退出页释放资源。云 TTS 使用现有可插拔 adapter/音频缓存；播放 20 次最多首次合成 1 次（同文本、声线、版本等缓存键稳定时）。Amazon Polly 官方确认允许缓存重复播放无额外合成费用：<https://aws.amazon.com/polly/faqs/>。
- 正式声线：中文 `Zhiyu` Neural、美式英语 `Ruth/Joanna` Generative、英式 `Amy/Brian` Generative；实际支持地区、引擎组合由 `DescribeVoices` 探测并以真实音质实听为准。当前 AWS 预算依旧 **0 元**，选择 AWS 不等于批准付费/把真实笔记发送给第三方。

## 2. 真实素材与翻译的完整性要求

### 2.1 内容处理顺序
1. 只读备份用户提供的 19 段 Markdown，保存 SHA-256、来源 `user_onsite_20261103`、原文字节和时间；原始素材暂处 Git 工作区 `docs/plan/content`，**禁止意外提交到公共 Git**；将正式生产副本保存在现有 Mac 私有 `SocialMate-Data` 下，授权访问，原仓库材料迁移/清理由主开发者先备份再执行。
2. “第一层：采集/归档”保留 19 段原话、各自英文 A、英文 B、备用说法、表达原表；源文的口误与半句话逐字不变。明确 `sourceStatus=complete|truncated|missing`，不能把 AI 补全冒充用户原话。
3. “第二层：翻译校对”：逐条补齐缺失的英文 A/B、短语对照，纠正不自然的直译/语法，英语表达以自然聊天为准，避免官方宣传口吻；新增结果标 `ai_suggested`，用户提供的原译标 `user_supplied`，并排可比较。至少 A/B 两种自然说法，可按需保留额外备选表达但不丢原句。
4. “第三层：学习块编排”在上层正确对齐后的双语结构上分段；每一块保留中文原文 `sourceSpan` 或 `originalSourceRef`、英语 A/B、短语/搭配、练习状态、版本、缓存音频引用，不能对一整份混排 Markdown 直接标点切句后再猜语言。
5. “第四层：入库”创建私有红城湖地点＋ 2026-11-03 一条完整游玩记录＋所有学习块，保存后退出重开、断网恢复、查看/编辑/撤回均可用。

### 2.2 图片与事实来源
- 优先使用用户自己拍的照片；若没有，由开发者整理适合手机呈现的合法来源，至少 3 张：湖景/步道、日常散步与运动场景、其他主题活动或儿童活动；逐图记录原始 URL、作者、拍摄年份、授权/许可、是否属实拍红城湖与适用范围。**没有许可不要直接抓报社/平台图片并打包重新分发**，没有特定场景照片就显示“尚无照片”，不能拿其他公园冒充。
- 已核实可合法复用的历史参考图：Wikimedia Commons `Hongcheng Lake 1.JPG`，Anna Frodesiak 摄于 2013-05-10，**CC0**，<https://commons.wikimedia.org/wiki/File:Hongcheng_Lake_1.JPG>；必须标注历史照片，不伪称2026现场。
- 正式背景资料优先市级权威资料：海口市 2026 红城湖公园养护项目（含设施维护），<https://ggzy.haikou.gov.cn/gonggao/91749>；晚间散步与广场舞的现场报道可用于交叉核查，<https://www.hainanfp.com/xinwen/2024/show-10101.html>。来源不同要标记：**政府/新闻事实、用户现场观察、AI翻译**，不得将2025历史价格/设施状态写成2026实时保证。

## 3. 字数上限与 AI 分段设置（明确、能测试）

**当前事实**：单条记录最多20,000 JavaScript 字符单位，红城湖 19 段Markdown 13,768单位可粘贴；但这只是单次输入接口限制，不是通用项目容量。缺少 UI 字数提示及超长草稿续传方案。

**V1.2 建议**：单次导入 UX 目标至少 **100,000 个 Unicode 字符**，输入实时显示字数/体积；客户端自动按原文位置拆为每批不超过现有服务端 20,000 上限的可恢复批次（后端需设计并验证草稿/批次/幂等/原子最终提交），所有批次完成后在**同一记录**中重组并校验原文 SHA。若手机性能/AI 成本风险大，允许先保留现有2万单批，但必须实现“继续添加下一批到同一记录”、超过时清晰提示且不丢稿；不能把一次输入截断或静默删除。不能将10万字符直接一次发 AWS Polly：官方 `SynthesizeSpeech` 每次最多3,000计费字符（6,000总字符）且输出不超过10分钟，必须按学习段合成。<https://docs.aws.amazon.com/polly/latest/dg/limits.html>

### 用户可选择的粒度
| 模式 | 建议目标 | 适用场景 |
|---|---|---|
| 精细 | 2–3 个完整语义句群，英文约20–45词 | 难句/新短语多；但不强制独立成很多两句小段 |
| **标准（默认）** | 3–5 个语义句群，英文约40–80词，通常20–45秒朗读 | 自然复习，优先在话题转折处停 |
| 宽松 | 5–8 个语义句群，英文约70–130词 | 已熟悉内容，合并回顾 |

句数/词数是**软目标**，优先主题完整性与中文—英文 A/B 对齐。AI 只提议断点，用户可拖动边界、合并/拆分、预览每段时长；原文不改、来源引用不变；改分段后 `blockId`/`revision` 及旧练习报告关联必须正确处理。记录级默认设置保存在“设置→学习与分段”，在编辑页提供临时切换；更改全局默认不自动重切旧记录。
