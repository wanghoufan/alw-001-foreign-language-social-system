- 默认浅色（墨水屏友好），同时提供浅/深可读样式；Android原生已强制浅色是临时安全修复，不能再引入白字白底，WebView需保持主题可读。
- 手机优先，Android WebView + 红米/小米自带浏览器先做；不以Chrome为唯一质量依据。无手机实时操作能力时完成浏览器模拟/代码层 QA，真实缺口标NOT_RUN，不能假造 PASS。

## P0｜基础纠偏：授权、连接/重传、可靠状态

### P0.1 原文留存授权
- 改掉 `AsrActivity.java` 当前 `retentionConsent.setChecked(true)`：新会话原文留存**默认未勾选**。录音同意与留存同意各自单独明确，AI同意仍由聊天页面控制；不得把用户曾经的录音同意当作永久留存同意。若保存偏好，必须额外提供明确的“今后默认留存”设置并可撤销；本阶段可先不记忆偏好。
- 测试：未勾选只识别/展示，不在 `current/outbox/exported` 写个人原文，不触发 Mac落盘；勾选且授权则允许，停止后仅final导出；取消同意后的后续会话不沿用授权，不改变旧已合法导出的资料。

### P0.2 断网自动补传和状态可见
- 在已有 `SessionArchive` 中审查 `flushAsync`/onCreate/onStop/按钮触发路径，补最小可靠的网络恢复触发与短退避（幂等、无高频常驻后台轮询、无无限重试烧电）；尊重Android前台运行与系统后台限制。必要时用 `ConnectivityManager` 的网络回调与受约束的持久任务方案，但不要凭空添加大型架构。
- 重要状态直接显示：`已保存手机，待上传 N 条` / `已同步 Mac` / `网络断开，自动重试` / `失败，可重试`，区分本地保存与Mac收妥，不把HTTP失败写成成功。
- 重连要防并发上传、重复归档及崩溃后丢失；错误、重启、重试不丢原文也不产生重复；服务端幂等与出队删除要核验。
- 必测：WiFi断开/恢复、网络切换、Mac服务短暂不可用、关闭重开、无令牌、Mac拒收、错误日志截断不泄密；能在可控测试中模拟的先模拟，不能真实操作手机则NOT_RUN。

### P0.3 安全/配置预检
- 复核 `archive-history.html` 中 `sm-archive-token` 的 localStorage 持久化风险，设计安全的手机私有授权复用：**绝不能把原始token直接注入URL、打进HTML、随意写JS可访问长期本地存储**。优先复用既有受限私有网关/受保护本机能力，验证来源认证与CSRF。若无法在本轮安全解决，只优化首配引导+短期会话凭据，保留显式输入/重验证，不因简化而降低安全。
- 安全配置目标：首次需要配置时有明确提示；之后正常连接尽量少重复输入；不可自动泄露服务器地址/令牌到其它域。
- P0验收：无留存授权0原文持久化；网恢复能一次性补传且幂等；鉴权/TLS/计费不回退；状态信息以用户能理解的中文呈现。

## P1｜资料统一与真正可检索

### P1.1 “人物”Tab统一到正式资料源
- 核查目前 V1.2 源码人物页 `SAV.people` 与 `GET /v12/api/people` + `People/<slug>/00-profile.md` 的关系，设计**一个正式权威资料源**：在线私有模式从被授权的本机正式档案读取人物名单、已确认事实、最近联系与来源；浏览器localStorage是缓存/草稿/离线演示。不能把旧 `SAV.people` 演示人物无提示地写正式 People；不能直接以客户端显示名改写slug。
- 提供按名字/备注搜索人物，人物详情可看到“已确认资料／上次聊过／下次可以聊”；基于确认资料，显示来源会话/时间；无数据时优雅空态，无需新建一级Tab。
- 如已有 Profile.sync，继续兼容“关于我”真实数据；标明 `仅本机临时资料` 与 `Mac 已确认资料` 区别，避免用户保存成功后不知道去哪找。先做读/展示，再做经过用户确认的写合并；不要造成双向不受控覆盖。
- 后端沿用鉴权令牌与同源私有 API，不把所有People原文或私人资料向公开站暴露。

### P1.2 新建人物目录标识免手填
- 保留现有显式“＋新建人物”与姓名确认；在填姓名时**本地自动生成安全唯一的slug建议**并允许高级手动修改。拉丁名可规整ASCII；中文等不支持的名字使用无意义的 `person-<日期>-<随机短码>` 或等价稳定ID，**不为转拼音调用额外付费AI/第三方服务**，不能从显示名反推身份。
- 后端继续合法slug正则/目录穿越拒绝/重名冲突提示；重名人与同名不同人必须独立ID，不自动合并档案。
- 全部新建必须用户主动确认保存（不能在输入名字瞬间正式建人）。删除/取消不留孤立空目录。

### P1.3 会话历史查找与基本管理
- 基于已有`archive-history.mjs` 的授权索引增加按日期、关键词、关联人物的筛选：优先**服务端授权检索**及分页/条数上限，避免一次性把全部历史原文拉到手机；人物关联必须来自用户确认的来源记录，不按说话人聚类猜。
- 默认只显示会话日期、段数、状态/归属人，点进去才看完整原文；关键词检索不通过第三方，不把搜索词写明文日志。保留现有 UTC 日期导出能力，并让用户清楚知道UTC与本地日期的区别；优先本地日期友好、后端UTC规范。
- **资料纠错/删除**先做“查看来源→撤回本条确认→再次确认”的安全方案；对已经进入Profile/People的事实做精准记录撤销、保留人工编写段落、不删整个文件；如果没有可靠源映射则安全拒绝并提示用户手工处理，绝不删错人。会话原文删除要单独二次确认与本机备份策略，不能凭一次点击清空真实库；真实删除用户自执行，开发只用隔离沙盒测。
- P1验收：新确认事实在人物Tab可看并搜索；旧本地草稿不污染正式主档；多人同名/新增/去重/权限正确；关键词搜索不跨人或漏权限；撤销不改写人工文本。

## P2｜实际社交价值：见面前准备、即时接话、英文积累

### P2.1 人物“见面前快速准备”
- 在现有“人物”Tab详情放一个**简短**的“见面前”区域，不扩散到其它四个Tab。展示：上次联系日期/上次两三个话题、已确认兴趣与重要事实、最多3条“这次可以接着问”的中英对照句、一个“暂时没有足够资料”空态。
- 优先**本地确定性模板/规则**从已确认Profile/People事实生成；用户明确同意向云端传送文字且个人资料上下文单独允许、受1元预算闸时才可选择AI润色。不得因为点“准备”就自动传私人档案到云端。
- 句子要普通人能开口，不编造自己的经历、对方身份、家庭/关系事实；每条建议有“来自已确认资料”的来源提示，推断与用户事实分开展示；人物身份不明只能显示通用模板。

### P2.2 聊天过程短句化
- 现有AI/规则建议卡的内容先审计；不重写推荐引擎。针对实时聊天呈现优先**一条自然接话 + 一条继续追问**（英文优先，中文释义简洁可切换，必要时可复制/朗读；若加朗读优先系统TTS不上传语音）。避免长解释卡堆满移动屏。
- 本地规则优先支持无网；AI用现有同意闸、冷却/去重、token预算限制。用户没有已确认“我也喜欢跑步”事实时不能生成此类个人事实。正常无关话题不强行推荐海南地点。
- 视图随字幕更新时稳定，不频繁闪烁跳动；反馈若用户正在录音操作不要抢占主要控制区。真实AI结果和本地模板在UI标清来源。

### P2.3 英文表达一键收藏与复习
- 在聊天建议/会后复盘句子旁增加“收藏表达”轻量入口；用户明确点击才保存到个人私有表达清单，保留英文、中文解释、可选来源/人物关联与时间。可快速浏览/朗读/复制；先不做间隔重复算法、记忆卡片大系统或额外一级Tab。
- 复用已有Profile/本地受保护数据存储，若需加字段或私有表，先写 schema/迁移/回滚/容量限制，不能覆写已有Profile.schema=1或产生第二套身份真相源；未确认私人原文不能因收藏功能被自动上传。
- P2验收：已确认人物信息确实能用于见面前提问；没有确认信息不编造；句子短且不遮挡聊天；收藏持久、重复不堆积、可找回/取消收藏，断网不向云端发请求。
