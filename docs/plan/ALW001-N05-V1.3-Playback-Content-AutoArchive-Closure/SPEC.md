## 2. 用户的核心播放语义（必须按完整序列，不可简化）
- 「听本段」= 播放**一整轮**：①整理版中文（zh）→②英文A（en）→③英文B（en）→④每个「常见表达」依次**中文释义(zh) → 1.0秒静音间隔 → 英文表达(en)**。阶段之间可配置小停顿但不超过干扰体验；每个词组的1秒间隔必须保证。
- 「循环」= 上述**同一完整队列**按用户选定次数重复，而**非只循环中文/英A/某个固定音频**；重复20轮是20个完整多语队列，验收要检查每轮元素数、次序和声音。
- 「听词组」= 只播放第④部分，逐条中文→1秒→英文；**不得**将 `coconut water 椰子水` 直接拼接扔给单声线朗读，也不应先英文后中文。
- 「听中文」「英A」「英B」= 仅播该单项，点即播，切换立即中断上一任务，不弹窗口。停播/暂停/继续、切段/离页停队列、循环显示进度、首次引擎初始化队列等待上限必须明确；切分语言要切正确voice。
- 朗读不应每次点都弹第三方授权。真实云端Provider仅在显式配置、有效预算及相应授权后调用；未配置就展示页面就地状态提示，允许用户选择本机系统语音离线兜底（仅用户选择）。不得静默外传文稿。
- 队列调度必须是由**真实音频完成回调**推进到下一段，而不是同步循环提交、吞掉上一任务或用固定总时长猜测；点击停止/切换后取消全部排队请求和旧回调；失败清晰标哪一节，提供重试，默认不可跳过英文以假装完整。支持系统TTS和remote adapter，缓存键含 provider/voice/lang/text hash/recordId/blockId/contentRevision。

## 3. 常用表达的结构化升级
- 现有 `phrases: string[]` 含仅英文、英文+中文混排、多候选斜线，不可简单按空格猜翻译。
- 新增向后兼容字段 `phrasePairs: [{id,zh,en,source,reviewStatus}]`（或复用经审计的已存在后端字段），每条中文和英文必须语义对应。原 `phrases` 只读保留，新增派生映射与来源信息，旧记录不覆写原始词组。
- 明确可解析才自动转换；仅英文或多义无法确定则标 `needs_review`、在UI显示缺失，不要编造、硬播或偷偷给未知英文加中文。AI建议和用户确认版本区分，授权前只能本地规则操作。
- 示例：`{zh:"椰子水",en:"coconut water"}`；实际播放 `zh → 1000ms silence → en`；分界处的静音由播放调度器计时/音频测量真实验证，不能只显示文案。
