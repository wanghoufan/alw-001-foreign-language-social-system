## 一、本轮改动

| 文件 | 改动 | 原因 |
|---|---|---|
| `assets/app.css` | `.fallback` 不再直接写 `display`，改为默认 `display:none` + `:not([hidden])` 才显示；照片加 `z-index:1`，提示降到 `z-index:0` | 旧写法让提示的 `display:grid` 与 `[hidden]` 抢显示状态，仅靠 `[hidden]` 上的 `!important` 才没盖住照片 |
| `assets/app.js` | `__n06ImgError` 改为「确认解码失败才报缺图」；加载中不再被 650ms 定时器误判 | 旧逻辑在图片仍在解码时会隐藏图片、亮出提示，形成“提示盖图” |
| `assets/app.js` | 「差异说明」弹层指向的文档名改为实际文件名 | 原引用 `运行验证.md` 与目录内文件不一致 |
| `verify.mjs` | 新增提示隐藏、图片可见、命中测试、像素证据、file:// 路径、反向自检所需断言 | 原断言只看 `naturalWidth`，提示盖在照片上也会通过 |
| `screenshots/` | 重新生成全部截图，新增 `02b`、`10` | 用可核对的证据替换旧图 |
| 新增 3 份文档 | `差异说明.md`、`截图索引.md`、`验证说明.md` | 交付说明 |

## 二、与正式 APP 的差异

### 2.1 详情图库取图链路（最关键）

- 正式版：公开地点详情调用 `smGallery()`（`socialmate-v1.2/index.html:1950`），该函数只读个人卡片的 `media`（`:968`、`:4139`），115 个公开地点从未进入卡片表，因此详情页不生成任何图片 DOM。结论与证据见 `docs/design/n06-audit/REPORT.md` 第一节。
- 本原型：详情与列表封面共用 `photoUrl()`，直接读取仓库归档 `docs/成果整理/Hainan-Travel-Guide/images/<城市目录>/<三位ID>/0N.webp`（`assets/app.js:40`），按 `photos` 槽位渲染。已核实错配或来源未登记的槽位登在 `photoExclusions`，渲染为“已排除（待核实）”（`assets/app.js:48` 起），不生成 `img`；没有归档的槽位显示“第 N 张缺失（待补图）”。两类都不借用其他地点图片。
- 其余未排除图片只表示“有清单记录”，页面统一标待核实，不写成已确认真实对应。
- 差异性质：原型是**对目标交互的演示**，不是对正式版缺图 Bug 的修复。正式版是否需要改、怎么改，仍待阶段 2 授权。

### 2.3 导航与页面结构

- 底部固定五个 Tab：`话题｜海南｜聊天｜关于我｜人物`（正式版当前仍含“软件”一级 Tab）。
- 原“软件”的搜索、分类、新建、回收站、中英介绍、讲解步骤迁到「话题 › 我的作品」，不是一张跳转卡。

- 默认浅色，可切深色/跟随系统；主题写入 `localStorage`（键 `n06.theme`）。

## 三、缺图提示遮挡照片：根因、修复与证据

### 3.1 现象与根因

- 现象：详情轮播里照片其实已加载，但“这张图片加载失败 / 真实缺图提示”浅色面板盖在照片上，用户以为没图。
- 根因：`.slide .fallback` 直接声明 `display:grid`（原 `app.css:232`），与隐藏机制抢同一个属性。隐藏只靠通用规则 `[hidden]{display:none!important}`（`app.css:43`）压住；一旦这条 `!important` 缺失、被覆盖或写入顺序变化，提示立刻显示并覆盖照片。
- 同类风险存在于 `.place-cover .fallback`（列表封面）与 `.lb-stage .fallback`（全屏）。

### 3.2 修复

1. `assets/app.css:213-218`：三个 `.fallback` 统一 `display:none`，只有 `:not([hidden])` 时才 `display:grid`。提示的显示状态不再与 `[hidden]` 抢属性。
2. `assets/app.css:241`、`426`：照片 `position:relative; z-index:1`，提示 `z-index:0`，即使用户态异常，照片也在提示之上。
3. `assets/app.js:73-88`：`__n06ImgError` 只在 `img.complete && naturalWidth === 0` 时判定缺图；仍在加载则继续等待（最多 5 秒），不再用固定 650ms 误杀慢图。

### 3.3 证据

- 正常态：`verify.mjs` 80 项全通过；三个 slide 的 `.fallback` 计算样式均为 `display:none`；`elementFromPoint` 在首图中心命中 `IMG`。
- 像素证据：截取首图区域（628×470）解码后，亮度标准差 82、量化颜色 2215 种、“缺图板底色”占比 0.000 —— 画面确实是照片。
- 反向自检：把旧写法注回（`.slide .fallback{display:grid}` 且照片不设层叠），同一套脚本立即红 5 项，同一区域像素的底色占比升到 0.947，说明断言确实能抓住这个缺陷，而不是“改了也绿”。

### 3.4 复现口径说明

接手时的工作区里，这条 `!important` 尚在，直接跑脚本时提示是隐藏状态，因此**未能原样复现**用户看到的遮挡画面；遮挡是通过“注回旧规则”的方式稳定复现的。这一点在 `验证说明.md` 中同样标注，不把“没复现”写成“没这个问题”。

## 四、未实现

8. 多语言切换 UI（页面本身是中英内容，但没有语言设置项）。

## 五、未验证

1. Android 真机（正式验收机 OPPO PLG110 / ColorOS）与 WebView 内的表现——本原型只在 macOS Chrome 无头模式下验证。
2. Safari / Firefox / Edge 的渲染差异。
3. 手机 WebView 通过 `file://` 打开时是否允许加载同目录子资源（Chrome 允许，WebView 常有限制）。
4. 211 张归档图片与地点的逐张对应关系与授权：本轮只核出并排除 11 张明确错配/无来源的图，其余图片来源仍未逐张重开来源页核验（沿用 `docs/design/n06-audit/REPORT.md` 的口径）。
5. 浏览器 `speechSynthesis` 朗读效果；它不等于豆包/TTS 验收。
6. 慢盘、大图、低端机下的首屏时序（本轮只验证了无头环境下的加载完成态）。
7. 触屏手势、无障碍读屏、横屏。
8. 关键依赖：`docs/成果整理/Hainan-Travel-Guide/images/` 被 `.gitignore:56` 排除，干净克隆或换机后多文件原型（`index.html`）没有照片，会如实显示缺图提示。新增的 `standalone-test/standalone.html` 已把 26 张可用图片内嵌进单文件，运行期不再依赖该目录；单文件体积 9.67 MiB，图片许可与来源仍需复核。

## 六、结论

本轮只把“照片已加载却被缺图提示遮挡”这一类问题从“靠一条 `!important` 侥幸成立”改为结构性不可能发生，并把校验从“看 `naturalWidth`”升级为“看提示状态 + 层叠命中 + 真实像素”。原型范围、内容性质与未验证项以上文为准，不构成对正式 APP 已修复的声明。
