## 1. 需求

用户场景：朋友说出一个不认识的词（如 capoeira），点它查看，并顺势把话题接下去。要求：

1. 保留中文解释；
2. 增加英文解释；
3. 问句要问对方的喜好、对比、体验、收获，**不能问"你听过吗"**（词本来就是对方说的）。

## 2. 实现

### 2.1 卡片

- 词头：词 + 「改查」+ 关闭。
- 中文解释：1–3 行。
- ENGLISH：1–3 行简单英文（B1），不提供例句（C1）。
- 顺势问对方：固定四条，顺序 `like / compare / experience / benefit`；每条中文一行 + 英文问句占整行 + 右侧「复制」。
- 「改查」收进标题栏，展开后才显示输入框与原句，默认不占高度；卡片一屏可见。

### 2.2 接口

`POST /api/ai/term`、Android `DirectCloud.term()` 同步返回：

```json
{
  "zh": "1–2 句中文解释",
  "en": "1–2 句简单英文",
  "asks": [
    {"kind": "like", "zh": "…", "en": "…"},
    {"kind": "compare", "zh": "…", "en": "…"},
    {"kind": "experience", "zh": "…", "en": "…"},
    {"kind": "benefit", "zh": "…", "en": "…"}
  ]
}
```

- Prompt 明确禁止询问对方是否听过/了解该词；英文每条 ≤12 词、自然口语；食物/地点/乐器/习俗自动换成味道/氛围/玩法/礼节的说法。
- 上游缺项时按 kind 补齐默认问句，保证卡片不空。
- 旧缓存（只有 `zh`）自动失效并重查。

### 2.3 修复

- 全局 `p{font-size:19px!important}` 覆盖了卡片小字号，导致四问每条 134px、整卡 961px；加作用域 `!important` 后压到 590px，一屏显示。

- 复制优先 `document.execCommand('copy')`，真实输入事件下成功；JS 合成 click 无手势时仍会提示受限（正常限制，不是缺陷）。
